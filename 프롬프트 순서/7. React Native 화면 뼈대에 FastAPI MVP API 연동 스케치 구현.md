## 제목

React Native 화면 뼈대에 FastAPI MVP API 연동 스케치 구현(라우팅 유지, 최소 상태 처리)

## Summary

현재 5개 화면의 목업 로직을 유지하되, 각 화면의 목적 API(세션 생성/조회/종료/공유/상태 체크)와 1:1로 매핑해 **직접 호출 가능한 최소 연동**으로 전환한다.  
전역 상태관리 없이 화면 단위 `useState + useEffect`와 공통 HTTP 유틸만 사용한다.

## 핵심 변경/추가

- 최소 공통 API 클라이언트 추가
  - `src/api/httpClient.js`(예시)에서 `requestJson({ method, path, body, headers })` 구현
  - `API_BASE_URL` 상수(예: `http://<PC_IP>:8000`) + `Authorization` 헤더 포맷(`Bearer ...`) 공통 처리
  - 기본 에러 메시지 반환/파싱 통일
- `DriverStart` API 연결
  - 버튼 클릭 시 `POST /api/v1/sessions` 호출
    - body: `driver_id`, `session_ttl_minutes`, `link_ttl_minutes`, `max_access_count`
    - headers: `Authorization: Bearer DRIVER_TOKEN_1` (우선 mock 토큰)
  - 응답(`session_id`, `link_token`, `link_url`, `session_status`, `expires_at`)을 표시하고 `DriverActiveSession`로 네비게이트
  - 실패/로딩 텍스트 최소 반영
- `DriverActiveSession` API 연결
  - “운전자 위치 조회” 버튼: `GET /api/v1/sessions/{session_id}/driver-location`
    - headers: `Authorization`(Bearer driver token) 또는 `X-Link-Token`(필요 시 대체)
    - 응답 `location`을 UI에 표시 (`none`이면 “아직 없음”)
  - “세션 종료” 버튼: `POST /api/v1/sessions/{session_id}/end` + body `{ reason: "driver_end" }`
  - 종료 성공 시 `SessionStateNotice`로 이동 (`status`, `ended_at`, `session_id` 전달)
- `PassengerLinkLanding` API 연결
  - 화면 진입 시 `GET /api/v1/links/{link_token}` 자동 호출
  - 응답의 `link_active`/`session_status` 기반으로 버튼 동작 전환
  - 실패/만료 시 `SessionStateNotice`로 이동(또는 에러 메시지)
- `PassengerShare` API 연결
  - 공유 시작 시 `setInterval`(예: 5초)로 `POST /api/v1/links/{link_token}/locations` 호출
    - body: `{ latitude, longitude, accuracy_m }`  
      (현재는 목업 좌표로 주기 업로드)
  - 공유 종료 시 interval 정리, 마지막 응답의 `saved_at/point_id` 표시
- `SessionStateNotice` API 연결
  - `linkToken` 존재 시 `GET /api/v1/links/{link_token}/status` 호출
  - `can_access`, `link_status`, `session_status`를 표시
  - 네트워크 실패는 “상태 확인 실패” 메시지로 표시

## 라우팅/호환성 제약(유지)

- 현재 `App.js`의 5개 화면 라우팅은 그대로 유지.
- 기존 네비게이션 파라미터(`sessionId`, `linkToken` 등) 형태를 유지하고, 필요한 API 결과를 `navigation.navigate`로 추가 전달.
- `react-native` 네이티브 지도/지도 권한/실시간 소켓/푸시/전역스토어는 추가하지 않음.

## 테스트 시나리오(수동)

1. Expo Go에서 `DriverStart` → “세션 생성” → 성공 응답 데이터 표시 및 `DriverActiveSession` 이동 확인
2. `DriverActiveSession`에서 “운전자 위치 조회” → `location` 또는 “없음” 렌더 확인
3. `PassengerLinkLanding`에서 링크 토큰으로 접근 → `/links/{link_token}` 응답 기반으로 “위치 공유 시작” 진입/만료 안내 분기 확인
4. `PassengerShare`에서 공유 시작 → 주기 요청 1회 이상 성공(`point_id`/`saved_at`) 표시 확인
5. `SessionStateNotice`에서 만료/종료 상태 반영(`can_access`) 확인
6. `DriverActiveSession`에서 세션 종료 → 상태 화면으로 이동하고, 같은 링크로 재확인 시 종료 반영 확인

## 가정/기본값

- API base URL은 수동 설정 가능한 상수/환경값으로 두고 기본은 로컬 개발 PC LAN IP 사용.
- 탑승자 공유 좌표는 MVP 범위에서 하드코딩 좌표/샘플 좌표로 대체(실기기 GPS 연동 제외).
- 앱 내 인증은 현재 설계 범위대로 `Authorization: Bearer` 헤더 최소 사용.

## 📚 [학습 관점의 상세 내용]

이번 단계는 단순한 화면 전환을 넘어, **실제 백엔드 서버(FastAPI)와 데이터를 주고받는 '생명력'을 불어넣는 과정**입니다. 리액트 네이티브 개발에서 가장 핵심이 되는 네트워크 통신 패턴을 학습합니다.

### 1. 비동기 통신과 `async / await` 패턴
네트워크 요청은 언제 응답이 올지 모르는 '비동기' 작업입니다. 자바스크립트의 `async/await`를 사용하면 복잡한 비동기 코드를 마치 순차적인 코드처럼 읽기 쉽게 작성할 수 있습니다.
*   **패턴**: `const response = await fetch(...)`
*   **장점**: 응답이 올 때까지 기다렸다가 다음 코드를 실행하므로 logic의 흐름을 파악하기 좋습니다.

### 2. 고전적인 에러 처리: `try...catch...finally`
서버 통신은 항상 실패할 가능성(네트워크 끊김, 서버 에러 등)이 있습니다. 이를 안전하게 처리하기 위해 반드시 이 삼단 구조를 사용합니다.
*   **try**: 정상적인 통신 로직을 시도합니다.
*   **catch**: 통신 중 에러가 발생하면 여기서 잡아내어 사용자에게 "실패했습니다"라고 알립니다.
*   **finally**: 성공하든 실패하든 마지막에 실행됩니다. 주로 **'로딩 스피너(ActivityIndicator)'**를 끄는 용도로 사용합니다.

### 3. 컴포넌트 생명주기와 `useEffect`
화면이 나타나자마자 자동으로 데이터를 불러와야 할 때(예: 링크 유효성 검사) `useEffect` 훅을 사용합니다.
*   **패턴**: `useEffect(() => { checkApi(); }, []);`
*   **주의점**: 비동기 작업 도중 사용자가 화면을 나가면 에러가 날 수 있으므로, `alive` 변수 같은 플래그를 사용하여 컴포넌트가 살아있을 때만 상태를 업데이트하는 기술(Cleanup 패턴)이 중요합니다.

### 4. 사용자 경험(UX)을 위한 로딩 처리
사용자는 버튼을 눌렀을 때 아무 반응이 없으면 앱이 멈췄다고 생각합니다.
*   **ActivityIndicator**: 서버와 통신 중임을 시각적으로 보여줍니다.
*   **Button disabled**: 통신 중에 버튼을 여러 번 누르지 못하게 막아 중복 요청을 방지합니다.

### 5. 화면 간 데이터 전달 (Route Params)의 심화
단순히 "넘어간다"는 개념을 넘어, 서버에서 받은 **진짜 ID(sessionId)**나 **인증 토큰(linkToken)**을 다음 화면으로 정확히 전달해야 합니다. 그래야 다음 화면에서 그 ID를 가지고 서버에 추가 정보를 물어볼 수 있습니다.

### 6. 공통 HTTP 클라이언트 (`httpClient.js`)
모든 화면에서 똑같은 `fetch` 코드를 작성하는 것은 비효율적입니다.
*   **공통화**: 서버 주소(Base URL), 헤더 설정, JSON 변환 로직을 한 곳에 모아 관리하면 유지보수가 매우 쉬워집니다.
*   **인증**: 모든 요청에 `Authorization` 헤더를 자동으로 붙여주는 구조를 미리 잡아두는 연습입니다.
