## React Native 최소 화면 구조 설계 (MVP)

### 요약

- 목표 화면 수를 최소화해 현재 백엔드 API 범위(세션 시작/링크 접속/위치 공유/운전자 위치 조회/세션 종료/링크 상태 확인)에만 대응한다.
- 예외 처리, 알림, 채팅, 인증 확장은 범위 밖으로 두고 핵심 동선만 설계한다.

### 화면 구성 (현재 기능 필요분만)

| 화면명                                 | 목적                                         | 주요 UI 요소                                                                           | 사용자 액션                                                                           |
| -------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 세션 시작 화면 (DriverStart)           | 운전자가 세션 생성 시작                      | 세션 생성 버튼, 탑승자 링크 출력 영역, 세션 만료/링크 만료 안내 텍스트                 | `세션 시작` 터치 -> API 호출 후 `session_id`/`link_token` 표시, 링크 복사/공유        |
| 세션 진행 화면 (DriverActiveSession)   | 생성된 세션을 운전자가 관리                  | 세션 상태(`active`/`ended`), 링크 토큰/만료시각, 운전자 위치 갱신 버튼, 종료 버튼      | `운전자 위치 조회` 트리거(폴링), `세션 종료` 버튼, 상태 실시간 표시                   |
| 링크 접속 화면 (PassengerLinkLanding)  | 탑승자가 링크 토큰으로 접근해 세션 상태 판정 | 링크 토큰 기반 세션 상태 카드, 세션 상태 메시지(활성/만료/종료), `위치 공유 시작` 버튼 | 링크 유효 시 `위치 공유 시작` 이동, 비활성 시 종료/만료 안내                          |
| 탑승자 위치 공유 화면 (PassengerShare) | 탑승자 위치 업로드(공유 시작)                | 권한 안내 라벨(위치), 현재 좌표 표시(선택), 전송 버튼 또는 자동 전송 상태 토글         | `공유 시작` 후 위치 업로드 시작(주기적 업로드), 공유 중지(세션 상태만료 시 자동 중단) |
| 상태 확인 화면 (SessionStateNotice)    | 세션 종료 또는 링크 만료를 별도 안내         | 상태 배지, `can_access` 안내, 재입장 안내 또는 앱 종료 동선                            | 링크 만료/세션 종료 확인 메시지 표시, 필요 시 `세션 시작 화면`/홈으로 이동            |

### 화면 간 이동 흐름도

```mermaid
flowchart LR
  S[세션 시작 화면<br/>DriverStart] --> A[세션 진행 화면<br/>DriverActiveSession]
  A -->|세션 종료| N[상태 확인 화면<br/>SessionStateNotice]
  A -->|운전자 위치 조회 Polling| A

  L[링크 URL 탭 or QR 진입] --> B[링크 접속 화면<br/>PassengerLinkLanding]
  B -->|link_active=true| C[탑승자 위치 공유 화면<br/>PassengerShare]
  B -->|link_active=false| N
  C -->|주기적 위치 업로드| C
  C -->|상태 조회/폴링 실패(만료)| N
```

### 각 화면의 최소 인터랙션 규칙

- 세션 시작 화면: 시작 즉시 `POST /api/v1/sessions`, 응답으로 받은 `link_token`은 다음 화면에 전달 또는 표시.
- 세션 진행 화면: 주기적으로 `GET /sessions/{session_id}/driver-location` 호출(운전자 토큰 필요). 종료 버튼은 `POST /sessions/{session_id}/end`.
- 링크 접속 화면: 열기 직후 `GET /links/{link_token}` 호출로 링크/세션 상태 확인.
- 탑승자 위치 공유 화면: 진입 후 `POST /links/{link_token}/locations`를 주기적으로 호출(또는 사용자가 “공유 시작” 후 시작).
- 상태 확인 화면: `GET /links/{link_token}/status` 기반으로 만료/종료 여부 표시.

### 테스트 시나리오 (수동 확인)

1. 운전자: 세션 시작 -> 링크 생성 및 공유 정보 표시되는지.
2. 탑승자: 링크 접속 -> `link_active=true`일 때 공유 화면으로 진입하는지.
3. 탑승자: 공유 화면에서 위치 업로드가 정상 호출되는지(최소 1회 이상 성공 응답).
4. 운전자: 진행 화면에서 `driver-location` 응답이 반영되어 위치 확인 가능한지.
5. 운전자: 세션 종료 후 링크 상태 확인에서 접근 불가/종료 상태가 반영되는지.
6. 만료 링크: 링크 접속 화면에서 상태 안내로 이동되고 공유가 차단되는지.

### 가정

- 사용자 인증/프로필은 기존 API 요구 수준(개발 토큰/간단 헤더) 유지.
- 폴링 주기(예: 5~10초)는 디바이스 성능에 따라 기본값으로만 정의하고 상세 튜닝하지 않음.
- 지도 렌더링/뷰 최적화, 권한 거부 재요청 UX, 백그라운드 위치 정책은 범위 밖.

오류 내용을 확인해보니, 현재 컴퓨터에 설치된 **Node.js 버전(v24.11.1)**이 너무 최신이거나 실험적인 버전이라 Expo(v50)와 충돌이 발생하고 있습니다. 특히 `node:sea`라는 폴더를 만들려고 시도하는데, 윈도우에서는 폴더 이름에 콜론(`:`)을 사용할 수 없어 발생하는 전형적인 운영체제 호환성 문제입니다.

이 문제를 해결하기 위한 두 가지 방법을 제안드립니다.

### 방법 1: Node.js 버전을 LTS(안정화 버전)로 변경 (가장 권장)

현재 사용 중인 v24는 개발용으로 너무 앞선 버전입니다. 실무와 대부분의 라이브러리에서 권장하는 **Node.js v20 (LTS)** 또는 **v22 (LTS)** 버전을 설치하시는 것이 가장 좋습니다.

1.  현재 Node.js를 삭제하거나, **NVM (Node Version Manager) for Windows**를 설치하여 버전을 전환해 주세요.
2.  **v20.x** 또는 **v22.x** 버전을 설치한 후 다시 시도해 주세요.

### 방법 2: Expo SDK 버전을 최신(v51 이상)으로 업데이트

최신 버전의 Expo는 이러한 윈도우 경로 문제를 해결했을 가능성이 높습니다. 아래 명령어를 통해 프로젝트의 Expo 버전을 올려보겠습니다.

```powershell
# react-native-app 폴더 안에서 실행
npx expo install expo@latest
npx expo start --clear
```

### 만약 위 방법들로도 안 된다면?

임시방편으로 **터널 모드**를 사용해 볼 수 있습니다. (네트워크 설정을 우회합니다.)

```powershell
npx expo start --tunnel
```
