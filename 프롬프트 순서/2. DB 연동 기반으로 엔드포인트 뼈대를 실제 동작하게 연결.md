# DB 연동 기반으로 엔드포인트 뼈대를 실제 동작하게 연결

DB 연동 기반으로 엔드포인트 뼈대를 실제 동작하게 연결했습니다.
라우터/스키마 구조는 유지하고 session_service의 비즈니스 로직을 PostgreSQL 조회·저장으로 교체했습니다.

변경/추가 파일

requirements.txt
app/main.py
app/db.py
app/models.py
app/services/session_service.py
연결 포인트

app/db.py: PostgreSQL 연결(DATABASE_URL) + SessionLocal + 앱 시작 시 create_all 초기화
app/models.py: 최소 3개 테이블 매핑 (pickup_sessions, session_links, location_points)
session_service.py:
create_session → 실제 세션/링크 INSERT
get_link_state → 링크·세션 상태 DB 조회 후 활성 여부 계산
share_passenger_location → location_points INSERT (actor_type=passenger)
get_driver_location → 세션/권한 최소 검증 후 최신 driver 위치 조회
end_session → 세션 상태 ended 갱신 + 링크 일괄 revoke
check_link_status → 링크/세션 만료/종료 상태 기반 계산 반환
main.py: 라우터 등록 유지, 시작 시 테이블 생성 보장
실행 준비

환경 변수 DATABASE_URL 필요(기본값은 postgresql+psycopg://postgres:postgres@localhost:5432/pickup_mvp)
설치/실행:
pip install -r requirements.txt
$env:DATABASE_URL="postgresql+psycopg://<user>:<pass>@<host>:5432/<db>"
uvicorn app.main:app --reload

## 학습 관점 포인트 (Learning Points)

인메모리 방식에서 실제 관계형 데이터베이스(PostgreSQL) 연동 방식으로 전환하면서 학습해야 할 핵심 기술적 포인트들입니다.

### 1. 트랜잭션 관리와 컨텍스트 매니저 (Context Manager)
- **`@contextmanager`**: `app/db.py`의 `get_db_session`은 파이썬의 컨텍스트 매니저를 사용하여 DB 세션의 생명주기를 관리합니다.
- **자동화된 작업**: `with` 블록을 사용할 때 작업이 성공하면 `db.commit()`을, 에러가 발생하면 `db.rollback()`을, 마지막엔 항상 `db.close()`를 수행하도록 설계되었습니다. 이는 데이터 무결성을 보장하고 리소스 누수를 방지하는 표준 패턴입니다.

### 2. SQLAlchemy 2.0 스타일 API
- **`select()`**: SQL 쿼리를 파이썬 코드로 선언적으로 작성하는 방식입니다.
- **`db.get(Model, id)`**: 기본 키(PK) 기반 조회를 위한 가장 빠르고 직관적인 방법입니다.
- **`db.scalar()` & `db.scalars()`**: 
    - `scalar()`는 쿼리 결과 중 첫 번째 행의 첫 번째 컬럼(보통 모델 객체 자체)을 하나만 가져옵니다.
    - `scalars().all()`은 여러 행의 결과 객체들을 리스트로 가져올 때 사용합니다.

### 3. 데이터 생명주기 관리: `add()` vs `flush()` vs `commit()`
- **`add()`**: 객체를 세션의 관리 대상으로 등록합니다 (아직 DB에 전송 안 됨).
- **`flush()`**: 변경 사항을 DB에 전송하여 실제 SQL을 실행하지만, **확정(Commit)은 하지 않은 상태**입니다. 이 단계에서 DB가 생성한 ID(Auto-increment ID 등)를 애플리케이션에서 즉시 사용할 수 있습니다.
- **`commit()`**: 모든 변경 사항을 영구적으로 반영합니다. 트랜잭션이 종료됩니다.

### 4. 관계형 데이터 모델링 (Relationship)
- **`ForeignKey`**: `session_links.session_id`가 `pickup_sessions.session_id`를 참조함으로써 데이터 간의 부모-자식 관계를 명시합니다.
- **`relationship`**: DB 수준의 외래키 연동을 넘어서, 파이썬 코드 레벨에서 `session.links`와 같이 객체 그래프를 순회하며 연관 데이터를 다룰 수 있게 해줍니다.
- **`cascade="all, delete-orphan"`**: 세션이 삭제될 때 연결된 링크나 위치 정보도 함께 삭제되도록 설정하여 데이터의 고아(Orphan) 발생을 막습니다.

### 5. 성능을 위한 쿼리 제어
- **`order_by(desc())` & `limit(1)`**: 운전자의 최신 위치를 조회할 때, 수만 개의 위치 기록 중 가장 최근의 1개만 효율적으로 가져오는 방법을 보여줍니다. 이는 시스템 부하를 최소화하는 필수적인 테크닉입니다.

### 6. 보안 및 권한 검증 (Stateless Auth)
- DB 모델에 `driver_token`과 `access_token`을 저장하고, API 요청 시마다 대조함으로써 세션이나 쿠키 없이도 각 호출의 유효성을 검증하는 **무상태(Stateless) 아키텍처**를 실현합니다.
- 단순 증감 ID가 아닌 `UUID`를 식별자로 사용하여 리소스 주소의 추측 공격(ID Enumeration)을 방어합니다.
