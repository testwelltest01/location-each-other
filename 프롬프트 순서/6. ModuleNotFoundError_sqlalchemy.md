## 제목

FastAPI 서버 재시작 시 `ModuleNotFoundError: sqlalchemy` 해결 계획 (Windows/uvicorn reload 환경)

## 요약

현재 오류는 코드 버그가 아니라 **실행 환경(파이썬 인터프리터/가상환경)에서 SQLAlchemy 패키지가 로드되지 않은 상태**에서 발생합니다.  
백엔드 실행 시 `uvicorn`이 구동되는 Python 환경에 `SQLAlchemy`가 설치되지 않았거나, reload 재시작 프로세스가 다른 인터프리터를 쓰는 경우가 원인입니다.

## 핵심 변경/실행 항목

- 의존성 패키지 상태 정합성 확인
  - `requirements.txt`에 `SQLAlchemy>=2.0`이 이미 있으므로, 문제는 패키지 미설치 또는 인터프리터 불일치입니다.
- 현재 실행 중인 Python 인터프리터 고정
  - `uvicorn` 실행 시 반드시 앱 코드와 같은 Python 환경에서 `python -m uvicorn app.main:app --reload`로 실행.
- 가상환경 기준으로 재설치(최소)
  - 새 가상환경 생성(또는 기존 venv 활성화) 후 `pip install -r requirements.txt` 재실행.
- reload 환경에서의 안전 실행 체크
  - `--reload`는 자식 프로세스에서 동일 환경을 재사용해야 하므로, `python -m uvicorn ...` 형태를 유지.
- 확인 로그 확인
  - 서버 재시작 후 `from sqlalchemy import ...` import 단계가 통과하는지 콘솔 로그 확인.

## API/모듈 영향

- 변경 대상은 런타임 실행 환경 정합성 뿐이며, 엔드포인트/DB 스키마/서비스 로직 인터페이스는 변경 없음.
- 목표 파일 범위(실행 파이프라인)만 정리:
  - `requirements.txt`(설치 기준)
  - 실행 커맨드(백엔드 실행 방법)

## 테스트 시나리오

1. 가상환경 진입 후 `python --version`, `python -m pip show SQLAlchemy` 출력 확인.
2. `python -m pip install -r requirements.txt` 완료.
3. `cd` 프로젝트 루트 → `python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000` 실행.
4. 서버 기동 후 `/` 호출 시 200 응답, startup 시 예외 없이 init_db 완료.
5. `python -m pytest`를 안 돌려도 되며(요청 범위 외), 최소 기능은 `/` + 세션 생성 한 번 호출로 동작 확인.

## 가정/기본값

- SQLAlchemy 자체 코드 호환성 문제는 아니며, 패키지 인식 문제임.
- 실행 시 PowerShell 기준 Python 3.13 사용 환경에서도 `sqlalchemy` 패키지 설치 가능한 상태라고 가정.
- DB URL/마이그레이션 이슈는 현재 단계 우선순위에서 제외(최소 목표는 import 에러 해소).
