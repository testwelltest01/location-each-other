# Naver Dynamic Map 최소 연동 계획 (DriverActiveSession, PassengerShare)

## Summary

두 화면에서만 지도 표시가 필요한 범위로, **Expo Go 환경에서도 동작 가능한 WebView 기반 Naver Dynamic Map 뼈대를 적용한다.  
지도 키는 코드 하드코딩 없이 환경변수에서 읽고, `EXPO_PUBLIC_`로 노출되는 클라이언트 키만 사용한다.  
`Client Secret`은 앱 프론트엔드에 주입하지 않고 미사용(클라이언트 키만 사용)으로 처리한다.**

## Key Changes / Implementation

- 지도 렌더링 모듈(최소 공통) 추가
  - `react-native-webview`로 WebView 지도 래퍼 1개 추가(`NaverDynamicMap`)를 두고, HTML 문자열로 Naver Map JS SDK를 로드 후 marker/center를 갱신.
  - 공통 props:
    - `clientId`(env)
    - `latitude`, `longitude`
    - `zoom`(기본 16)
    - `markerTitle`/`markerText`
    - 좌표가 없으면 기본 좌표(예: 서울 시청)로 지도 출력.
  - 지도 키 입력 방식:
    - `process.env.EXPO_PUBLIC_NAVER_MAP_CLIENT_ID`

- `DriverActiveSession` 연동
  - 기존 `fetchDriverLocation` API 응답의 좌표를 지도 마커 좌표로 전달.
  - 좌표가 존재하면 지도 중심을 해당 좌표로 이동.
  - `Get driver-location` 버튼 동작 후 지도 마커가 갱신되도록 상태 바인딩.
  - (요구사항 문구상 “탑승자 위치 표시”로 반영되더라도, 현재 API 스코프를 유지해 `/sessions/{session_id}/driver-location` 응답 좌표를 지도 마커로 표시)

- `PassengerShare` 연동
  - `expo-location`로 현재 위치 권한을 요청 후 좌표 획득.
  - 현재 좌표를 지도에 실시간(버튼 시작 시 최초 1회 + 주기 공유 때 재조회) 반영해 마커 표시.
  - 공유 POST(`POST /links/{link_token}/locations`)에 현재 위치 좌표 사용.
  - 공유 중에도 위치가 바뀌면 마커 갱신(최소 단계: 매 공유 주기마다 재조회).

- 앱/네이티브 설정
  - `package.json`에 최소 의존성 추가:
    - `react-native-webview`
    - `expo-location`
  - `app.json`에 필수 기본 ID/번들 고정:
    - iOS: `ios.bundleIdentifier = com.pickup.session.mobile`
    - Android: `android.package = com.pickup.session.mobile`
  - 위치 권한 최소 설정 추가:
    - iOS `NSLocationWhenInUseUsageDescription`
    - Android `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`
  - 네이티브 모듈식 네이버 지도 패키지를 추가하지 않고, Expo Go에서 유지 가능한 방식으로 구성.

- 문서 정리
  - `mobile-run.md` 또는 짧은 신규 문서에 환경변수 설정 예시 추가:
    - `EXPO_PUBLIC_NAVER_MAP_CLIENT_ID`
    - (선택) `EXPO_PUBLIC_NAVER_MAP_CLIENT_SECRET` 설명: **백엔드/서버 전용, 앱에서 사용 금지**
  - 실행 확인 체크리스트 1~2줄 포함:
    - 지도 표시/마커 표시/좌표 이동 동작

## Assumptions / Defaults

- 실행 환경은 Expo Go 기반(따라서 네이티브 Naver Map SDK 패키지 미사용, WebView 방식 적용).
- 키는 클라이언트에 `Client ID`만 노출 가능(`Client Secret`은 프론트엔드 미사용).
- 기존 API 인터페이스는 변경하지 않음(현재 MVP 엔드포인트 유지).
- 지도/마커는 단일 마커, 경로/ETA/소켓/푸시/고급 권한 UX 미구현으로 유지.

## 📚 [학습 관점의 상세 내용]

이번 단계에서는 앱에 '지도'라는 시각적 요소를 통합하고, 실제 기기의 GPS 하드웨어를 제어하는 방법을 학습했습니다.

### 1. WebView를 활용한 지도 렌더링 (Bridge 패턴 기초)
네이티브 개발에서 특정 기능을 웹 기술(HTML/JS)로 구현하여 앱 안에 삽입하는 방식을 학습했습니다.
*   **왜 WebView인가?**: Expo Go와 같은 제한된 환경에서 복잡한 네이티브 설정 없이도 강력한 웹 SDK(네이버 지도 JS SDK)를 그대로 사용할 수 있기 때문입니다.
*   **HTML 주입**: React Native의 상태(State) 값을 HTML 문자열 안에 템플릿 리터럴(`${...}`)로 주입하여, 앱의 데이터가 웹 화면에 반영되도록 했습니다.

### 2. 환경변수와 보안 (`EXPO_PUBLIC_`)
민감한 정보인 API 키를 코드에 직접 쓰지 않고 관리하는 방법을 익혔습니다.
*   **EXPO_PUBLIC_**: 이 접두사가 붙은 변수는 빌드 시점에 클라이언트 코드에 포함되어 앱 내에서 `process.env`로 접근 가능하게 됩니다.
*   **클라이언트 키 vs 시크릿 키**: 네이버 지도처럼 화면 표시만 필요한 경우 클라이언트 ID만 노출하고, 보안이 중요한 Secret Key는 서버(FastAPI) 측에서만 사용해야 한다는 보안 원칙을 학습했습니다.

### 3. 하드웨어 접근: 위치 권한 (Location Permission)
스마트폰의 민감한 정보인 GPS 데이터를 가져오기 위한 운영체제(OS) 수준의 보안 절차를 이해했습니다.
*   **권한 요청 flow**: 단순히 함수를 호출하는 것이 아니라, 먼저 사용자에게 '허용'을 받고(Request Permissions), 허용된 경우에만 데이터를 가져오는 비동기 흐름을 익혔습니다.
*   **app.json 설정**: Android(AndroidManifest)와 iOS(info.plist)에서 앱이 왜 위치 정보가 필요한지 명시하는 설정법을 배웠습니다.

### 4. 실시간 데이터와 지도의 동기화
GPS에서 얻은 실시간 좌표가 어떻게 지도의 마커로 시각화되는지 연결 과정을 학습했습니다.
*   **상태 바인딩**: `currentLocation` 상태가 바뀔 때마다 `NaverDynamicMap` 컴포넌트가 리렌더링되며 WebView의 HTML이 갱신되어, 사용자는 마커가 움직이는 것처럼 느끼게 됩니다.
*   **데이터 정밀도**: GPS 오차(`accuracy`) 정보를 함께 전송하여 데이터의 신뢰도를 관리하는 기초를 다졌습니다.

### 5. 컴포넌트 재사용성
`NaverDynamicMap`이라는 공통 컴포넌트를 만들어, 운전자 화면과 탑승자 화면 등 서로 다른 목적의 화면에서 똑같은 지도 로직을 재사용하는 효율적인 구조를 설계했습니다.
