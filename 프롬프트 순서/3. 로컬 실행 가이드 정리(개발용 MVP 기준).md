## 최소 테스트용 요청 예시
- 운전자 세션 생성: `POST /api/v1/sessions`
- 탑승자 링크 접속: `GET /api/v1/links/{link_token}`
- 탑승자 위치 공유: `POST /api/v1/links/{link_token}/locations`
- 운전자 위치 조회: `GET /api/v1/sessions/{session_id}/driver-location`
- 세션 종료: `POST /api/v1/sessions/{session_id}/end`
- 링크 상태 확인: `GET /api/v1/links/{link_token}/status`

## 학습 관점 포인트 (Learning Points)

로컬 실행 환경을 구축하고 테스트 시나리오를 작성하면서 반드시 숙지해야 할 포인트들입니다.

### 1. 인프라의 코드화 (Infrastructure as Code - IaC)
- **`docker-compose.yml`**: 데이터베이스와 API 서버와 같은 인프라 구성을 코드로 작성하여 관리합니다. 이는 프로젝트 환경을 어디서나 동일하게 재현할 수 있게 해주는 현대적인 개발 필수 기술입니다.

### 2. 컨테이너의 격리와 오케스트레이션
- **완전 격리**: 내 컴퓨터에 직접 PostgreSQL을 설치하지 않아도 컨테이너 내부의 격리된 환경에서 DB를 실행할 수 있습니다.
- **오케스트레이션**: `depends_on`을 사용하여 DB가 먼저 실행된 후 API 서버가 동작하도록 컨테이너 간의 실행 순서를 조율하는 기초적인 오케스트레이션 기법을 익힐 수 있습니다.

### 3. 데이터 보존과 실시간 코드 동기화
- **볼륨 (Volume)**: `pickup_db_data` 볼륨을 통해 컨테이너가 꺼져도 DB 데이터가 유지되는 원리를 배웁니다.
- **바인드 마운트 (Bind Mount)**: 호스트의 소스 폴더와 컨테이너 내부 폴더를 연결하여, 코드를 수정할 때마다 컨테이너를 다시 빌드하지 않고도 즉시 반영(Reload)되는 효율적인 개발 환경 구성을 경험합니다.

### 4. 네트워크 서비스 디스커버리
- **DNS (서비스 이름)**: 컨테이너 내부 네트워크에서는 IP 주소 대신 `db`라는 이름만으로 상대 서비스에 자동 접속할 수 있습니다. 이를 통해 유동적인 네트워크 환경에서도 안정적으로 통신하는 법을 익힙니다.

### 5. API 테스트와 검증 자동화의 기초
- **cURL을 통한 유효성 검증**: 브라우저 UI 없이도 터미널에서 직접 HTTP 요청을 보냄으로써 API의 입출력 구조를 정확히 파악할 수 있습니다.
- **헬스 체크 (Health Check)**: 시스템이 정상인가를 가장 간단하게 확인하는 `/` 엔드포인트의 중요성을 배웁니다.
- **시나리오 테스트**: 세션 생성 → 링크 접속 → 위치 공유 → 종료로 이어지는 전체 비즈니스 흐름을 직접 따라가며 데이터의 상태 변화를 추적하는 법을 학습합니다.
