# 화면 설계서

## 1. 문서 목적

본 문서는 픽업 특화 위치 기반 서비스의 주요 화면을 정의하기 위한 문서이다.  
서비스 개요, 유저 플로우, 기능 정의서를 바탕으로 실제 사용자에게 제공될 화면 단위를 식별하고, 각 화면의 목적, 구성 요소, 사용자 행동, 상태 변화, 예외 상황을 정리한다.

이 문서의 목적은 다음과 같다.

- 서비스의 기능을 실제 UI 화면 단위로 구체화한다.
- 운전자와 탑승자 각각의 화면 흐름을 명확히 한다.
- 화면별 핵심 정보, 주요 액션, 상태 분기를 정의한다.
- 추후 와이어프레임, 프로토타입, UI 디자인, 프론트엔드 개발의 기준을 제공한다.

---

## 2. 화면 설계 원칙

본 서비스는 일반적인 지도 탐색 앱이 아니라, **운전자와 탑승자가 빠르게 만나도록 돕는 픽업 특화 앱**이므로 화면 설계에서도 다음 원칙을 따른다.

### 2.1 최소 조작 원칙

운전 중 또는 급한 상황에서도 사용할 수 있도록 화면 조작 수를 최소화한다.

### 2.2 상태 중심 설계

각 화면은 단순 정보 표시가 아니라 “지금 사용자가 어떤 단계에 있는가”를 즉시 이해할 수 있도록 상태 중심으로 설계한다.

### 2.3 역할 분리 설계

운전자와 탑승자는 동일한 세션을 공유하지만 필요 정보와 액션이 다르므로 화면 구성도 분리한다.

### 2.4 핵심 행동 우선 배치

화면마다 사용자가 반드시 해야 하는 핵심 행동을 가장 눈에 띄게 배치한다.

### 2.5 예외 상황 가시화

위치 권한 거부, 링크 만료, 위치 오차, 연결 지연 등 주요 예외 상황을 별도 화면 또는 상태 안내로 분명히 드러낸다.

---

## 3. 화면 구조 개요

MVP 기준 화면은 크게 다음 두 사용자 흐름으로 나뉜다.

### 3.1 운전자 화면군

1. 홈 화면
2. 픽업 세션 생성 화면
3. 링크 공유 화면
4. 탑승자 연결 대기 화면
5. 실시간 픽업 지도 화면
6. 근접/도착 확인 화면
7. 픽업 완료 화면

### 3.2 탑승자 화면군

1. 링크 진입 화면
2. 위치 권한 요청 화면
3. 위치 공유 진행 화면
4. 운전자 접근 확인 화면
5. 픽업 완료 화면

### 3.3 공통/예외 화면군

1. 링크 만료 화면
2. 위치 권한 거부 안내 화면
3. 네트워크 오류 화면
4. 위치 정확도 낮음 안내 상태

## 5. 운전자 화면 상세 설계

---

### S-01. 홈 화면

#### 화면 목적

운전자가 앱에 진입한 후 픽업 기능을 시작할 수 있도록 한다.

#### 주요 사용자

- 운전자

#### 핵심 질문

- 지금 바로 누군가를 픽업하려는가?
- 새로운 픽업 세션을 시작할 준비가 되었는가?

#### 주요 구성 요소

- 상단 서비스명 또는 로고
- 메인 CTA 버튼: `픽업 시작`
- 최근 세션 여부 또는 안내 문구
- 간단한 사용 설명(선택)

#### 주요 액션

- 픽업 시작 버튼 선택

#### 다음 화면

- S-02 픽업 세션 생성 화면

#### 설계 포인트

- 홈 화면은 복잡할 필요가 없다.
- 앱의 주요 목적이 픽업 시작임을 즉시 알 수 있어야 한다.

---

### S-02. 픽업 세션 생성 화면

#### 화면 목적

운전자가 새로운 픽업 세션을 생성하도록 한다.

#### 주요 사용자

- 운전자

#### 주요 구성 요소

- 화면 제목: `픽업 세션 시작`
- 안내 문구: `탑승자에게 보낼 초대 링크를 생성합니다`
- 진행 버튼: `세션 생성`
- 로딩 상태 표시

#### 주요 액션

- 세션 생성 버튼 선택

#### 시스템 반응

- 세션 생성 요청
- 성공 시 링크 발급 준비
- 실패 시 오류 메시지 표시

#### 다음 화면

- 성공 시 S-03 링크 공유 화면
- 실패 시 E-03 네트워크 오류 화면 또는 인라인 에러

#### 설계 포인트

- 운전자는 기술적 개념(세션)을 이해할 필요가 없으므로 설명은 간단하게 유지한다.
- 실제 UI에서는 “세션 생성”보다 “픽업 요청 만들기” 같은 표현이 더 자연스러울 수 있다.

---

### S-03. 링크 공유 화면

#### 화면 목적

운전자가 탑승자에게 픽업 요청 링크를 전달할 수 있도록 한다.

#### 주요 사용자

- 운전자

#### 주요 구성 요소

- 생성된 링크 표시 영역
- `링크 복사` 버튼
- `공유하기` 버튼
- 안내 문구: `탑승자가 링크를 열고 위치 공유를 시작하면 경로를 확인할 수 있습니다`

#### 주요 액션

- 링크 복사
- 외부 앱으로 공유
- 공유 완료 후 다음 단계 이동

#### 다음 화면

- S-04 연결 대기 화면

#### 설계 포인트

- 이 화면의 핵심은 “링크를 쉽게 보내는 것”이다.
- 탑승자에게 앱 설치를 요구하지 않는 구조라면 이 화면의 중요도가 매우 높다.

---

### S-04. 연결 대기 화면

#### 화면 목적

탑승자가 링크를 열고 위치 공유를 시작하기 전까지의 상태를 안내한다.

#### 주요 사용자

- 운전자

#### 주요 구성 요소

- 상태 메시지
  - 예: `탑승자가 아직 링크를 열지 않았습니다`
  - 예: `탑승자가 위치 공유를 준비 중입니다`
- 로딩 또는 대기 표시
- `링크 다시 공유` 버튼
- `취소` 버튼(선택)

#### 주요 액션

- 대기
- 링크 재공유
- 세션 취소

#### 상태 분기 예시

- 링크 미접속
- 링크 접속 완료
- 위치 권한 요청 중
- 위치 공유 시작 직전

#### 다음 화면

- 위치 공유 시작 시 S-05 실시간 픽업 지도 화면

#### 설계 포인트

- “앱이 멈춘 것처럼 보이지 않게 하는 것”이 핵심이다.
- 실시간 상태 문구가 자주 바뀌더라도 사용자가 혼란스럽지 않게 표현을 정리해야 한다.

---

### S-05. 실시간 픽업 지도 화면

#### 화면 목적

운전자가 탑승자의 현재 위치를 보고 길안내를 시작하도록 한다.

#### 주요 사용자

- 운전자

#### 주요 구성 요소

- 전체 지도
- 내 위치 마커
- 탑승자 위치 마커
- 상단 상태 바
  - 예: `탑승자 위치 공유 중`
- 하단 정보 패널
  - 탑승자와의 거리
  - 예상 도착 시간
  - 마지막 위치 갱신 시각
- 핵심 버튼
  - `길안내 시작`
  - `픽업 완료`
- 보조 버튼
  - `새로고침`
  - `링크 다시 보내기`(선택)

#### 주요 액션

- 탑승자 위치 확인
- 길안내 시작
- 이동 중 상태 확인

#### 상태 분기 예시

- 위치 정상 수신
- 위치 정확도 낮음
- 위치 갱신 지연
- 탑승자 이동 중

#### 다음 화면

- 길안내 시작 후 동일 화면 유지 또는 내비게이션 모드 진입
- 근접 시 S-06 근접/도착 확인 화면

#### 설계 포인트

- 이 화면이 서비스의 핵심 화면이다.
- 지도 외에 너무 많은 정보를 넣으면 운전 중 가독성이 떨어진다.
- “탑승자 위치”와 “운전자 행동” 사이의 연결이 분명해야 한다.

---

### S-06. 근접/도착 확인 화면

#### 화면 목적

운전자가 탑승자 근처에 도착했을 때 마지막 만남을 쉽게 할 수 있도록 한다.

#### 주요 사용자

- 운전자

#### 주요 구성 요소

- 상단 상태 표시: `탑승자 근처에 도착했습니다`
- 축소 또는 확대된 근거리 지도
- 탑승자와의 남은 거리
- `도착 알림 보내기` 버튼(선택)
- `픽업 완료` 버튼
- `탑승자 위치 다시 보기` 버튼

#### 주요 액션

- 도착 확인
- 픽업 완료 처리

#### 상태 분기 예시

- 근접 상태
- 매우 근접 상태
- 위치 오차 존재
- 탑승자 이동 중

#### 다음 화면

- S-07 픽업 완료 화면

#### 설계 포인트

- 마지막 50m~100m의 혼선을 줄이는 데 초점을 둔다.
- 향후 버전에서는 차량 접근 가능 지점 안내가 이 화면과 연결될 수 있다.

---

### S-07. 픽업 완료 화면 (운전자)

#### 화면 목적

세션이 종료되었음을 명확히 알리고, 위치 공유가 중단되었음을 보여준다.

#### 주요 사용자

- 운전자

#### 주요 구성 요소

- 완료 메시지: `픽업이 완료되었습니다`
- 보조 메시지: `위치 공유가 종료되었습니다`
- `홈으로 이동` 버튼
- `새 픽업 시작` 버튼(선택)

#### 주요 액션

- 홈 이동
- 새 세션 시작

#### 설계 포인트

- 세션이 끝났다는 사실을 확실히 보여줘야 한다.
- 개인정보 보호 측면에서 “위치 공유 종료” 문구가 중요하다.

---

## 6. 탑승자 화면 상세 설계

---

### S-08. 링크 진입 화면

#### 화면 목적

탑승자가 초대 링크를 통해 픽업 세션에 들어오도록 한다.

#### 주요 사용자

- 탑승자

#### 주요 구성 요소

- 화면 제목: `픽업 위치 공유`
- 안내 문구: `현재 위치를 공유하면 운전자가 더 쉽게 찾아올 수 있습니다`
- `위치 공유 시작하기` 버튼
- 서비스 간단 설명
- 세션 유효성 확인 결과

#### 주요 액션

- 위치 공유 시작하기

#### 다음 화면

- S-09 위치 권한 요청 화면

#### 설계 포인트

- 탑승자는 이 서비스에 익숙하지 않을 가능성이 크므로, “왜 이걸 해야 하는지”를 짧고 명확하게 전달해야 한다.

---

### S-09. 위치 권한 요청 화면

#### 화면 목적

탑승자에게 위치 권한을 요청하고 동의를 얻는다.

#### 주요 사용자

- 탑승자

#### 주요 구성 요소

- 권한 필요 설명 문구
  - 예: `현재 위치를 공유해야 운전자가 정확히 찾아올 수 있습니다`
- `위치 권한 허용` 버튼
- `나중에 할게요` 또는 `취소` 버튼(정책에 따라 선택)

#### 주요 액션

- 권한 허용
- 권한 거부 또는 이탈

#### 상태 분기 예시

- 권한 허용 성공
- 권한 거부
- 기기 설정상 위치 비활성화

#### 다음 화면

- 허용 시 S-10 위치 공유 진행 화면
- 거부 시 E-02 권한 거부 안내 화면

#### 설계 포인트

- 권한 요청은 시스템 팝업 전에 먼저 서비스 자체 안내 문구를 주는 것이 좋다.
- 사용자는 자신의 위치가 언제까지 공유되는지 알고 싶어할 수 있다.

---

### S-10. 위치 공유 진행 화면

#### 화면 목적

탑승자가 현재 위치가 정상적으로 공유되고 있음을 확인하도록 한다.

#### 주요 사용자

- 탑승자

#### 주요 구성 요소

- 상태 메시지: `현재 위치를 공유 중입니다`
- 간단한 지도 또는 위치 확인 영역
- 보조 정보
  - 예: `운전자가 이 위치를 보고 이동 중입니다`
  - 예: `위치 공유는 픽업 완료 시 자동 종료됩니다`
- `위치 공유 중지` 버튼(정책에 따라 노출 여부 결정)
- `현재 위치 다시 확인` 버튼(선택)

#### 주요 액션

- 대기
- 필요 시 위치 공유 중지
- 위치 상태 확인

#### 상태 분기 예시

- 위치 공유 중
- 위치 정확도 낮음
- 네트워크 불안정
- 위치 갱신 중지

#### 다음 화면

- 운전자 접근 시 S-11 운전자 접근 확인 화면
- 세션 종료 시 S-12 픽업 완료 화면

#### 설계 포인트

- 탑승자는 복잡한 경로를 볼 필요가 없을 수 있다.
- 핵심은 “내 위치가 잘 공유되고 있는가”에 대한 신뢰를 주는 것이다.

---

### S-11. 운전자 접근 확인 화면

#### 화면 목적

운전자가 가까이 도착했음을 탑승자에게 알려 마지막 만남을 쉽게 만든다.

#### 주요 사용자

- 탑승자

#### 주요 구성 요소

- 상단 메시지
  - 예: `운전자가 곧 도착합니다`
  - 예: `운전자가 근처에 있습니다`
- 간단한 거리/도착 예상 정보
- 필요 시 작은 지도
- 안내 문구
  - 예: `눈에 잘 띄는 위치에서 기다려 주세요`

#### 주요 액션

- 대기
- 운전자 식별
- 필요 시 더 잘 보이는 곳으로 이동

#### 상태 분기 예시

- 3분 이내 도착
- 근접 상태
- 운전자 위치 갱신 지연

#### 다음 화면

- 픽업 완료 시 S-12 픽업 완료 화면

#### 설계 포인트

- 탑승자에게 지나치게 많은 정보보다 “곧 도착” 감각을 주는 것이 중요하다.
- 이 화면은 불안을 줄이는 역할을 한다.

---

### S-12. 픽업 완료 화면 (탑승자)

#### 화면 목적

위치 공유가 종료되고 픽업이 완료되었음을 안내한다.

#### 주요 사용자

- 탑승자

#### 주요 구성 요소

- 완료 메시지: `픽업이 완료되었습니다`
- 보조 문구: `위치 공유가 종료되었습니다`
- `닫기` 버튼

#### 주요 액션

- 화면 종료

#### 설계 포인트

- 탑승자에게도 위치 공유가 끝났음을 명확히 알려야 한다.
- 신뢰와 안전감 형성 측면에서 중요하다.

---

## 7. 예외 화면 상세 설계

---

### E-01. 링크 만료 화면

#### 화면 목적

유효하지 않은 링크 또는 종료된 세션에 접속한 경우 이를 안내한다.

#### 주요 사용자

- 탑승자

#### 주요 구성 요소

- 오류 메시지: `이 링크는 만료되었거나 더 이상 유효하지 않습니다`
- 보조 문구: `운전자에게 새 링크를 요청해 주세요`
- `닫기` 버튼

#### 발생 조건

- 세션 종료 후 재접속
- 잘못된 링크
- 유효시간 초과

#### 설계 포인트

- 사용자가 “내가 뭘 잘못했는가?”보다 “다음에 무엇을 해야 하는가?”를 알 수 있어야 한다.

---

### E-02. 권한 거부 안내 화면

#### 화면 목적

탑승자가 위치 권한을 허용하지 않은 경우 왜 권한이 필요한지 다시 안내한다.

#### 주요 사용자

- 탑승자

#### 주요 구성 요소

- 메시지: `위치 공유를 허용해야 운전자가 정확히 찾아올 수 있습니다`
- `다시 권한 요청` 버튼
- `설정으로 이동` 버튼(가능한 경우)
- `취소` 버튼

#### 발생 조건

- 위치 권한 거부
- OS 설정상 위치 비활성화

#### 설계 포인트

- 강압적 표현보다 목적 중심 설명이 필요하다.
- 권한 없이는 핵심 기능이 성립하지 않는다는 점을 분명히 해야 한다.

---

### E-03. 네트워크 오류 화면

#### 화면 목적

세션 생성, 링크 접속, 위치 수신, 경로 탐색 등에서 네트워크 문제가 발생했을 때 안내한다.

#### 주요 사용자

- 운전자 / 탑승자

#### 주요 구성 요소

- 메시지: `네트워크 연결이 원활하지 않습니다`
- 보조 문구: `연결 상태를 확인한 뒤 다시 시도해 주세요`
- `다시 시도` 버튼
- `이전 화면으로` 버튼

#### 발생 조건

- API 호출 실패
- 위치 갱신 실패
- 지도/경로 로딩 실패

#### 설계 포인트

- 에러의 기술적 원인보다 사용자가 취할 수 있는 행동을 우선 보여줘야 한다.

---

### E-04. 위치 정확도 낮음 상태

#### 화면 목적

실내, 지하, 건물 밀집 구역 등에서 위치 오차가 클 때 이를 안내한다.

#### 주요 사용자

- 운전자 / 탑승자

#### 주요 구성 요소

- 상태 배지 또는 경고 문구
  - 예: `현재 위치 정확도가 낮습니다`
- 보조 안내
  - 탑승자용: `가능하면 야외나 더 넓은 공간으로 이동해 주세요`
  - 운전자용: `탑승자의 실제 위치와 차이가 있을 수 있습니다`

#### 발생 조건

- GPS 정확도 임계값 이하
- 위치 수신은 되지만 신뢰도 낮음

#### 설계 포인트

- 반드시 별도 전체 화면일 필요는 없고, 주요 화면 내부 상태 패널로도 구현 가능하다.
- 단, 상태가 눈에 띄게 드러나야 한다.

→ S-03 링크 공유

## 9. 화면 설계 시 추가 고려 사항

### 9.1 운전자 안전성

운전자 화면은 운전 중 조작을 최소화해야 하므로, 큰 버튼과 단순한 정보 구조가 필요하다.

### 9.2 탑승자 설치 장벽 최소화

탑승자 화면은 링크 진입 후 즉시 사용할 수 있어야 하며, 회원가입이나 복잡한 입력은 MVP에서 제외하는 것이 적절하다.

### 9.3 상태 메시지 일관성

“연결 중”, “위치 공유 중”, “도착 임박”, “완료” 등의 문구는 전 화면에서 일관된 용어 체계를 유지해야 한다.

### 9.4 종료의 명확성

픽업 완료 후에는 양측 모두에게 위치 공유 종료를 분명히 안내해야 한다.

### 9.5 확장 가능성

향후 공항/행사장/캠퍼스 특화 픽업 모드가 들어갈 수 있으므로, 화면 구조는 상태 배지나 모듈형 정보 패널을 확장할 수 있게 설계하는 것이 바람직하다.

## 10. MVP 기준 필수 화면

초기 버전에서 반드시 필요한 화면은 다음과 같다.

### 운전자

- 홈 화면
- 링크 공유 화면
- 연결 대기 화면
- 실시간 픽업 지도 화면
- 픽업 완료 화면

### 탑승자

- 링크 진입 화면
- 위치 권한 요청 화면
- 위치 공유 진행 화면
- 픽업 완료 화면

### 예외

- 링크 만료 화면
- 권한 거부 안내 화면
- 네트워크 오류 상태

즉, MVP는 “설명 없이 위치를 공유하고, 운전자가 그 위치를 보고 실제로 도달하는 경험”을 성립시키는 최소 화면 집합으로 구성한다.

## 11. 정리

본 서비스의 화면 설계는 단순히 지도 화면을 만드는 것이 아니라,  
**운전자와 탑승자가 픽업이라는 짧지만 혼란스러운 상황을 최소한의 조작으로 통과하도록 돕는 구조를 만드는 것**에 목적이 있다.

핵심은 다음과 같다.

- 운전자는 빠르게 픽업을 시작하고 탑승자 위치를 보아야 한다.
- 탑승자는 복잡한 절차 없이 위치를 공유해야 한다.
- 시스템은 각 단계의 상태를 명확히 보여줘야 한다.
- 픽업 완료 후에는 위치 공유 종료를 분명히 알려야 한다.

이 문서는 이후 와이어프레임 설계, UX 문구 설계, UI 시안 제작, 프론트엔드 화면 구현의 기준 문서로 활용한다.
