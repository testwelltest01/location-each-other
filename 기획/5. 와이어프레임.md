# 와이어프레임 초안

## 1. 문서 목적

본 문서는 픽업 특화 위치 기반 서비스의 주요 화면을 저충실도(low-fidelity) 수준에서 구조화하기 위한 초안 문서이다.
이 문서는 실제 UI 디자인 시안 이전 단계에서, 각 화면에 어떤 정보와 기능이 어떤 우선순위로 배치되어야 하는지 정리하는 데 목적이 있다.

와이어프레임 단계에서는 색상, 시각 스타일, 브랜드 표현보다 다음 요소를 우선한다.

- 화면 내 정보 구조
- 주요 버튼의 위치
- 사용자 시선 흐름
- 핵심 행동 유도 구조
- 상태별 화면 분기

즉, 본 문서는 “예쁘게 만드는 문서”가 아니라, **사용자가 헷갈리지 않게 움직일 수 있는 화면 골격을 설계하는 문서**이다.

---

## 2. 와이어프레임 설계 원칙

### 2.1 한 화면, 한 핵심 행동

각 화면은 가능한 한 하나의 핵심 행동만 수행하도록 설계한다.
예를 들어 홈 화면에서는 “픽업 시작”, 탑승자 진입 화면에서는 “위치 공유 시작”, 완료 화면에서는 “종료 확인”이 핵심 행동이 된다.

### 2.2 지도는 중심이 아니라 도구

본 서비스에서 지도는 중요하지만, 지도 자체가 목적은 아니다.
사용자는 지도를 보려는 것이 아니라 **상대방과 정확히 만나기 위해 필요한 정보**를 얻고자 한다. 따라서 지도 위에도 상태 정보와 핵심 버튼이 함께 구조화되어야 한다.

### 2.3 운전자 화면은 조작 최소화

운전자는 이동 중일 수 있으므로, 버튼 수를 줄이고 정보 밀도를 낮추며 큰 액션 중심으로 배치한다.

### 2.4 탑승자 화면은 설명 최소화

탑승자는 앱에 익숙하지 않을 수 있으므로, 설치나 회원가입 없이 가능한 한 적은 단계로 위치 공유를 시작할 수 있어야 한다.

### 2.5 예외 상황도 화면이다

권한 거부, 링크 만료, 네트워크 오류 같은 상황은 부가 문제가 아니라 핵심 UX이다. 따라서 별도 상태 화면 또는 상태 영역으로 설계한다.

---

## 3. 와이어프레임 표기 규칙

본 문서에서는 텍스트 기반 박스 구조를 사용해 화면 골격을 표현한다.

- `[상단바]` : 상단 헤더 영역
- `[본문]` : 메인 콘텐츠 영역
- `[버튼]` : 주요 액션 버튼
- `[패널]` : 정보 요약 또는 상태 표시 영역
- `[지도]` : 지도 표시 영역
- `[하단고정]` : 고정형 액션 바

실제 디자인 단계에서는 이 구조를 바탕으로 시각 요소를 정교화한다.

# 4. 운전자 화면 와이어프레임

---

## W-01. 홈 화면

### 화면 목적

운전자가 앱에 들어온 직후 픽업을 시작할 수 있도록 한다.

### 와이어프레임 구조

```text
┌──────────────────────┐
│ [상단바] 서비스명     │
├──────────────────────┤
│                      │
│   픽업 특화 안내문구  │
│   “사람을 목적지로    │
│    설정해 보세요”     │
│                      │
│   [버튼] 픽업 시작    │
│                      │
│   최근 세션/안내문구  │
│                      │
├──────────────────────┤
│ [하단] 간단 설명/정보 │
└──────────────────────┘
```

### 핵심 요소

- 서비스명 또는 로고
- 핵심 CTA: `픽업 시작`
- 짧은 보조 설명

### 사용자 행동

- 픽업 시작 선택

### 설계 메모

- 가장 중요한 것은 첫 화면에서 망설임이 없어야 한다는 점이다.
- 버튼은 화면 중앙 또는 하단 가까이에 크고 분명하게 둔다.

---

## W-02. 픽업 세션 생성 화면

### 화면 목적

운전자가 픽업 세션 생성을 실행하도록 한다.

### 와이어프레임 구조

```text
┌──────────────────────────┐
│ [상단바] 픽업 시작       │
├──────────────────────────┤
│                          │
│  탑승자에게 보낼 링크를   │
│  생성합니다               │
│                          │
│  [버튼] 세션 생성         │
│                          │
│  생성 중 로딩 영역        │
│                          │
└──────────────────────────┘
```

### 핵심 요소

- 설명 문구
- 세션 생성 버튼
- 로딩 상태

### 설계 메모

- 실제 UI에서는 이 화면을 별도 페이지가 아니라 바텀시트나 모달로 줄일 수도 있다.
- 다만 기획상으로는 독립 단계로 보는 것이 명확하다.

---

## W-03. 링크 공유 화면

### 화면 목적

운전자가 탑승자에게 위치 공유 링크를 전달하도록 한다.

### 와이어프레임 구조

```text
┌────────────────────────────┐
│ [상단바] 링크 공유         │
├────────────────────────────┤
│                            │
│  탑승자에게 아래 링크를     │
│  보내 주세요                │
│                            │
│  [패널] 링크 표시 영역      │
│  https://pickup/...        │
│                            │
│  [버튼] 링크 복사           │
│  [버튼] 공유하기            │
│                            │
│  보조 안내 문구             │
│                            │
├────────────────────────────┤
│ [하단고정] 다음 단계로      │
└────────────────────────────┘
```

### 핵심 요소

- 링크 표시
- 복사 버튼
- 외부 공유 버튼

### 설계 메모

- `링크 복사`와 `공유하기` 중 무엇이 주 행동인지 결정해야 한다.
- 메신저 공유 비율이 높다면 `공유하기`가 더 우선일 수 있다.

---

## W-04. 연결 대기 화면

### 화면 목적

탑승자의 접속 및 위치 공유 시작 여부를 운전자에게 안내한다.

### 와이어프레임 구조

```text
┌────────────────────────────┐
│ [상단바] 탑승자 연결 대기   │
├────────────────────────────┤
│                            │
│   [상태 아이콘]            │
│                            │
│   현재 상태 메시지          │
│   “상대방이 아직 링크를     │
│    열지 않았습니다”         │
│                            │
│   보조 상태 문구            │
│   - 링크 전송 완료          │
│   - 접속 대기 중            │
│                            │
│   [버튼] 링크 다시 공유     │
│   [버튼] 세션 취소          │
│                            │
└────────────────────────────┘
```

### 상태 분기 예시

- 아직 링크 미접속
- 링크 접속 완료
- 위치 권한 요청 중
- 위치 공유 시작 대기

### 설계 메모

- 대기 화면은 정적인 화면이 아니라 상태 메시지가 바뀌는 화면이다.
- 사용자가 “왜 아직 안 되지?”라고 생각하지 않게 단계가 보여야 한다.

---

## W-05. 실시간 픽업 지도 화면

### 화면 목적

운전자가 탑승자의 위치를 확인하고 길안내를 시작한다.

### 와이어프레임 구조

```text
┌────────────────────────────────┐
│ [상단바] 픽업 진행 중          │
├────────────────────────────────┤
│ [상태배지] 위치 공유 중        │
│ [상태배지] 마지막 갱신 10초 전 │
├────────────────────────────────┤
│                                │
│            [지도]              │
│   - 내 위치 마커               │
│   - 탑승자 위치 마커           │
│   - 필요 시 경로 표시          │
│                                │
│                                │
├────────────────────────────────┤
│ [패널] 거리 / ETA / 상태        │
│ - 남은 거리                     │
│ - 예상 도착 시간                │
│ - 위치 정확도                   │
├────────────────────────────────┤
│ [버튼] 길안내 시작              │
│ [버튼] 픽업 완료                │
└────────────────────────────────┘
```

### 핵심 요소

- 지도
- 상태 배지
- 거리/ETA 정보
- 길안내 시작 버튼

### 설계 메모

- 실제 디자인에서는 지도 위에 floating button을 둘지, 하단고정 버튼을 둘지 결정해야 한다.
- 운전자 관점에서 가장 중요한 정보는 `어디에 있는가`, `얼마나 남았는가`, `지금 바로 이동하면 되는가`이다.

---

## W-06. 근접/도착 확인 화면

### 화면 목적

운전자가 탑승자 근처에 도착했을 때 마지막 만남을 돕는다.

### 와이어프레임 구조

```text
┌──────────────────────────────┐
│ [상단바] 곧 만날 수 있어요    │
├──────────────────────────────┤
│ [상태 강조] 탑승자 근처 도착  │
│                              │
│         [근거리 지도]         │
│                              │
│ [패널] 남은 거리 매우 짧음    │
│ [패널] 위치 오차 가능 안내    │
│                              │
│ [버튼] 도착 알림 보내기       │
│ [버튼] 픽업 완료              │
└──────────────────────────────┘
```

### 설계 메모

- 이 화면은 추후 차량 접근 가능 지점 추천 기능이 붙기 좋은 위치다.
- MVP에서는 단순히 “거의 도착했다”는 상태 강조만으로도 의미가 있다.

---

## W-07. 픽업 완료 화면 (운전자)

### 화면 목적

픽업이 끝나고 세션이 종료되었음을 알린다.

### 와이어프레임 구조

```text
┌──────────────────────────────┐
│ [상단바] 픽업 완료           │
├──────────────────────────────┤
│                              │
│      완료 아이콘/체크         │
│                              │
│   픽업이 완료되었습니다       │
│   위치 공유가 종료되었습니다  │
│                              │
│   [버튼] 홈으로 이동          │
│   [버튼] 새 픽업 시작         │
│                              │
└──────────────────────────────┘
```

### 설계 메모

- 종료 이후에도 사용자가 불안하지 않게 “위치 공유 종료”를 명확히 표시한다.

# 5. 탑승자 화면 와이어프레임

---

## W-08. 링크 진입 화면

### 화면 목적

탑승자가 링크를 통해 서비스에 진입하고 위치 공유를 시작하도록 유도한다.

### 와이어프레임 구조

```text
┌──────────────────────────────┐
│ [상단바] 픽업 위치 공유      │
├──────────────────────────────┤
│                              │
│  운전자가 더 쉽게 찾을 수     │
│  있도록 현재 위치를 공유해    │
│  주세요                       │
│                              │
│  [버튼] 위치 공유 시작하기    │
│                              │
│  보조 설명                    │
│  - 별도 주소 입력 없음        │
│  - 픽업 완료 시 자동 종료     │
│                              │
└──────────────────────────────┘
```

### 설계 메모

- 이 화면은 신뢰 형성이 중요하다.
- 너무 많은 설명은 이탈을 만든다. 핵심 메시지는 짧아야 한다.

---

## W-09. 위치 권한 요청 화면

### 화면 목적

탑승자가 위치 권한을 허용하게 한다.

### 와이어프레임 구조

```text
┌──────────────────────────────┐
│ [상단바] 위치 권한 요청      │
├──────────────────────────────┤
│                              │
│   현재 위치를 공유해야        │
│   운전자가 정확히 찾아올 수   │
│   있습니다                    │
│                              │
│   [버튼] 위치 권한 허용       │
│   [텍스트버튼] 취소           │
│                              │
│   보조 설명                   │
│   “픽업 완료 시 자동 종료”    │
│                              │
└──────────────────────────────┘
```

### 설계 메모

- 시스템 권한 팝업 직전의 프리퍼미션(pre-permission) 화면 역할이다.
- 사용자는 언제 끝나는지 알면 거부 확률이 낮아질 수 있다.

---

## W-10. 위치 공유 진행 화면

### 화면 목적

탑승자가 자신의 위치가 정상적으로 공유되고 있음을 확인한다.

### 와이어프레임 구조

```text
┌──────────────────────────────┐
│ [상단바] 위치 공유 중        │
├──────────────────────────────┤
│ [상태배지] 공유 활성화       │
│                              │
│         [간단 지도]           │
│       또는 위치 표시 카드     │
│                              │
│ [패널] 현재 상태              │
│ - 운전자가 이 위치를 보고     │
│   이동 중입니다               │
│ - 마지막 갱신 시각            │
│                              │
│ [버튼] 위치 공유 중지         │
│                              │
└──────────────────────────────┘
```

### 설계 메모

- 탑승자에게는 상세 내비보다 “공유가 잘 되고 있다”는 확신이 중요하다.
- 너무 많은 정보 대신 상태 중심 패널이 적절하다.

---

## W-11. 운전자 접근 확인 화면

### 화면 목적

운전자가 가까이 도착했음을 알려 대기 행동을 돕는다.

### 와이어프레임 구조

```text
┌──────────────────────────────┐
│ [상단바] 곧 도착합니다       │
├──────────────────────────────┤
│                              │
│  운전자가 근처에 있습니다     │
│                              │
│  [패널] 예상 도착             │
│  - 2분 이내 도착             │
│  - 근처에서 기다려 주세요    │
│                              │
│  [선택] 작은 지도/위치 안내   │
│                              │
└──────────────────────────────┘
```

### 설계 메모

- 탑승자에게는 정교한 경로보다 “이제 준비해야 한다”는 신호가 더 중요하다.

---

## W-12. 픽업 완료 화면 (탑승자)

### 화면 목적

탑승자에게 위치 공유가 종료되었음을 알린다.

### 와이어프레임 구조

```text
┌──────────────────────────────┐
│ [상단바] 완료                │
├──────────────────────────────┤
│                              │
│      완료 아이콘/체크         │
│                              │
│   픽업이 완료되었습니다       │
│   위치 공유가 종료되었습니다  │
│                              │
│   [버튼] 닫기                │
│                              │
└──────────────────────────────┘
```

### 설계 메모

- 위치 정보와 관련된 불안감을 줄이는 데 중요하다.

# 7. 핵심 화면 우선순위

## MVP에서 먼저 그릴 화면

가장 먼저 와이어프레임을 더 구체화해야 하는 핵심 화면은 다음과 같다.

1. 운전자 실시간 픽업 지도 화면
2. 탑승자 링크 진입 화면
3. 탑승자 위치 권한 요청 화면
4. 탑승자 위치 공유 진행 화면
5. 운전자 연결 대기 화면

이 다섯 개가 실제 서비스 성립 여부를 결정한다.

# 8. 추가 설계 메모

## 8.1 지도 중심 레이아웃 vs 패널 중심 레이아웃

운전자 화면은 지도가 주가 되어야 하지만, 정보패널이 너무 약하면 현재 상태를 해석하기 어렵다.
따라서 지도 60~70%, 하단 상태 패널 30~40% 정도 구성이 초기안으로 적절할 수 있다.

## 8.2 버튼 우선순위

한 화면에 강한 버튼은 1개, 보조 버튼은 최대 1~2개로 제한하는 것이 좋다.
버튼이 많아지면 픽업 상황의 긴장감 속에서 오작동 가능성이 커진다.

## 8.3 상태 문구 표준화 필요

예를 들어 다음 문구는 이후 UX 라이팅 문서에서 표준화해야 한다.

- 연결 대기 중
- 위치 공유 중
- 이동 중
- 근처 도착
- 픽업 완료
- 위치 정확도 낮음

## 8.4 탑승자 화면의 지도 필요성 재검토

탑승자에게 큰 지도는 꼭 필요하지 않을 수 있다.
위치 공유 진행 화면에서 지도 대신 현재 상태 카드만 넣는 방식이 더 단순하고 나을 가능성도 있다.
이 부분은 실제 프로토타입 단계에서 비교 검토가 필요하다.

# 9. 정리

이 와이어프레임 초안은 실제 디자인 시안을 그리기 위한 출발점이다.
중요한 것은 각 화면이 **어떤 정보를 어떤 순서로 보여주고, 사용자에게 어떤 행동을 요구하는지**를 먼저 고정하는 것이다.

본 서비스의 핵심 화면 설계 방향은 다음과 같다.

- 운전자는 빠르게 픽업을 시작하고 현재 위치 기반으로 움직여야 한다.
- 탑승자는 최소 단계로 위치 공유를 시작해야 한다.
- 시스템은 현재 상태를 이해하기 쉽게 보여줘야 한다.
- 예외 상황도 흐름의 일부로 설계해야 한다.

다음 단계에서는 이 초안을 바탕으로 다음 작업 중 하나로 이어질 수 있다.

1. 화면별 상세 와이어프레임 고도화
2. 컴포넌트 정의서 작성
3. UX 라이팅 문서 작성
4. Figma용 프레임 구조 문서 작성
5. 프론트엔드 페이지 구조 설계
