# 유저 플로우

## 1. 문서 목적

본 문서는 픽업 특화 위치 기반 서비스의 핵심 사용자 흐름을 정의하기 위한 문서이다.  
서비스 개요에서 정의한 문제와 목표를 바탕으로, 실제 사용자가 어떤 순서로 서비스를 이용하고 어떤 시점에서 어떤 상호작용이 발생하는지를 구조화한다.

이 문서의 목적은 다음과 같다.

- 운전자와 탑승자의 주요 행동 흐름을 명확히 정의한다.
- 서비스의 핵심 기능이 어떤 사용 맥락에서 작동하는지 정리한다.
- 정상 흐름과 예외 흐름을 구분하여 이후 화면 설계 및 기능 명세의 기준으로 삼는다.
- MVP 단계에서 반드시 구현해야 할 사용자 경험의 핵심 경로를 도출한다.

---

## 2. 주요 사용자 역할

본 서비스는 두 명의 핵심 사용자 간 상호작용을 중심으로 구성된다.

### 2.1 운전자

- 탑승자를 데리러 가는 사용자
- 픽업 요청을 생성하고, 탑승자의 위치를 받아 경로를 따라 이동한다.
- 목표는 빠르고 정확하게 탑승자를 찾는 것이다.

### 2.2 탑승자

- 운전자에게 픽업을 요청받거나 픽업을 기다리는 사용자
- 자신의 현재 위치를 간단히 공유하고, 운전자와의 만남을 준비한다.
- 목표는 복잡한 설명 없이 자신의 위치를 전달하는 것이다.

---

## 3. 전체 사용자 흐름 개요

서비스의 기본 구조는 아래와 같다.

1. 운전자가 픽업을 시작한다.
2. 탑승자에게 위치 공유 요청이 전달된다.
3. 탑승자가 위치 공유를 수락한다.
4. 운전자가 탑승자의 실시간 위치를 확인한다.
5. 운전자가 해당 위치를 기준으로 픽업 경로를 안내받는다.
6. 필요 시 탑승자 위치 변화가 반영된다.
7. 두 사람이 만나면 픽업이 완료된다.
8. 위치 공유 세션이 종료된다.

즉, 이 서비스의 핵심은 “장소를 찾는 흐름”이 아니라 “사람에게 도달하는 흐름”을 설계하는 데 있다.

---

## 4. 핵심 플로우 1: 운전자 중심 메인 흐름

### 4.1 픽업 시작

운전자는 앱에 진입한 후 “픽업 시작” 기능을 선택한다.

#### 운전자 행동

- 앱 실행
- “픽업 시작” 버튼 선택

#### 시스템 반응

- 새로운 픽업 세션 생성
- 탑승자에게 전달할 초대 링크 또는 요청 코드 발급

#### 목적

- 픽업 상황을 하나의 실시간 세션으로 시작하기 위함

---

### 4.2 탑승자 초대

운전자는 생성된 초대 링크를 탑승자에게 전달한다.

#### 운전자 행동

- 링크 복사
- 메신저, 문자 등 외부 수단으로 탑승자에게 전달

#### 시스템 반응

- 공유 가능한 링크 생성
- 세션 상태를 “초대 전송됨”으로 변경

#### 목적

- 탑승자가 별도 설명 없이 즉시 위치 공유 절차에 진입할 수 있도록 함

---

### 4.3 탑승자 연결 대기

운전자는 탑승자가 링크를 열고 위치 공유를 시작할 때까지 대기한다.

#### 운전자 행동

- 대기 화면 확인
- 탑승자 연결 여부 모니터링

#### 시스템 반응

- 현재 상태 표시  
  예: “상대방이 아직 링크를 열지 않았습니다”

#### 목적

- 픽업이 아직 시작되지 않았음을 명확히 인지하게 함

---

### 4.4 탑승자 위치 수신

탑승자가 위치 공유를 허용하면, 운전자는 지도 위에서 탑승자의 실시간 위치를 확인할 수 있다.

#### 운전자 행동

- 지도 화면 진입
- 탑승자 위치 확인
- 길안내 시작 선택

#### 시스템 반응

- 지도에 탑승자 위치 표시
- 내 위치와 탑승자 위치를 함께 노출
- 예상 거리 및 예상 도착 시간 계산

#### 목적

- 운전자가 더 이상 설명을 듣지 않고도 바로 이동을 시작할 수 있도록 함

---

### 4.5 픽업 이동

운전자는 탑승자 위치를 기준으로 이동한다.

#### 운전자 행동

- 경로 안내를 따라 운전
- 필요 시 재탐색 확인

#### 시스템 반응

- 현재 위치 기반 경로 제공
- 탑승자 위치가 유의미하게 변경될 경우 경로 갱신
- 도착 예상 시간 지속 업데이트

#### 목적

- 픽업 이동 중에도 최신 상황을 반영하도록 함

---

### 4.6 근접 및 도착

운전자가 탑승자 근처에 도달하면, 픽업 마무리 단계로 진입한다.

#### 운전자 행동

- 도착 여부 확인
- 탑승자를 시각적으로 탐색
- 필요 시 “도착 알림” 전송
- 픽업 완료 버튼 선택

#### 시스템 반응

- 근접 상태 표시
- 탑승자에게 차량 접근 상태 전달 가능
- 픽업 완료 시 세션 종료 준비

#### 목적

- 마지막 만남 단계에서 혼선을 줄이고 세션을 종료할 준비를 함

---

### 4.7 픽업 완료

두 사람이 만나면 운전자가 픽업 완료를 선택한다.

#### 운전자 행동

- “픽업 완료” 선택

#### 시스템 반응

- 위치 공유 중단
- 세션 종료
- 후속 화면 이동

#### 목적

- 불필요한 위치 추적을 방지하고 서비스 흐름을 종료함

---

## 5. 핵심 플로우 2: 탑승자 중심 메인 흐름

### 5.1 링크 수신

탑승자는 운전자로부터 초대 링크를 받는다.

#### 탑승자 행동

- 메신저/문자에서 링크 확인
- 링크 클릭

#### 시스템 반응

- 세션 진입 페이지 표시
- 서비스 소개 및 위치 공유 요청 안내

#### 목적

- 탑승자가 앱 설치 여부와 관계없이 빠르게 흐름에 들어오도록 함

---

### 5.2 위치 공유 동의

탑승자는 현재 위치를 공유하기 위해 권한 요청을 받는다.

#### 탑승자 행동

- 위치 권한 허용
- 공유 시작 선택

#### 시스템 반응

- 기기 위치 수집 시작
- 세션 상태를 “위치 공유 중”으로 변경
- 운전자 화면에 현재 위치 전달

#### 목적

- 탑승자가 별도 주소 입력 없이 현재 위치를 전달하게 함

---

### 5.3 위치 공유 유지

탑승자는 운전자가 도착할 때까지 위치를 공유한다.

#### 탑승자 행동

- 현재 위치 유지
- 필요 시 이동
- 화면에서 운전자의 접근 여부 확인

#### 시스템 반응

- 일정 주기 또는 조건에 따라 위치 업데이트
- 운전자에게 최신 위치 전달

#### 목적

- 탑승자의 위치 변화가 픽업 성공을 방해하지 않도록 함

---

### 5.4 운전자 접근 확인

운전자가 근처에 오면 탑승자는 차량 도착 상황을 확인한다.

#### 탑승자 행동

- 차량 접근 상태 확인
- 눈에 띄는 위치로 이동하거나 대기
- 운전자를 식별

#### 시스템 반응

- 도착 임박 상태 표시
- 필요 시 “운전자가 근처에 도착했습니다” 안내

#### 목적

- 마지막 만남 단계에서 탑승자의 대기 효율을 높임

---

### 5.5 픽업 완료

운전자와 만나 차량에 탑승하면 세션이 종료된다.

#### 탑승자 행동

- 차량 탑승
- 별도 조작 없이 흐름 종료 또는 완료 확인

#### 시스템 반응

- 위치 공유 중단
- 세션 만료 또는 종료 표시

#### 목적

- 위치 공유가 더 이상 지속되지 않도록 안전하게 종료함

---

## 6. 메인 유저 플로우 요약

### 6.1 운전자 플로우

앱 실행 → 픽업 시작 → 링크 생성 및 전송 → 탑승자 연결 대기 → 위치 수신 → 길안내 시작 → 이동 → 근접 → 픽업 완료

### 6.2 탑승자 플로우

링크 수신 → 링크 접속 → 위치 권한 허용 → 위치 공유 시작 → 대기 또는 이동 → 운전자 접근 확인 → 탑승 → 종료

---

## 7. 상태 기반 플로우 정의

본 서비스는 단순 길찾기 서비스가 아니라 실시간 세션 기반 서비스이므로, 주요 상태를 명확히 정의할 필요가 있다.

### 7.1 세션 상태 초안

1. 세션 생성됨
2. 링크 전송됨
3. 탑승자 미접속
4. 탑승자 접속 완료
5. 위치 권한 요청 중
6. 위치 공유 시작됨
7. 운전자 이동 중
8. 탑승자 이동 중
9. 근접 상태
10. 픽업 완료
11. 세션 종료

이 상태 정의는 이후 기능 명세서, 백엔드 로직, 화면 분기 처리의 기준이 된다.

## 8. 예외 플로우

정상 흐름만으로는 실제 픽업 상황을 충분히 설명할 수 없으므로, 주요 예외 상황을 별도로 정리한다.

### 8.1 탑승자가 링크를 열지 않음

#### 상황

운전자가 링크를 보냈지만 탑승자가 일정 시간 내 접속하지 않음

#### 시스템 대응

- “상대방이 아직 연결되지 않았습니다” 안내
- 링크 재전송 기능 제공

---

### 8.2 탑승자가 위치 권한을 거부함

#### 상황

탑승자가 위치 공유 권한을 허용하지 않음

#### 시스템 대응

- 권한 필요 이유를 재안내
- 수동 위치 지정 기능 검토 가능
- 현재 단계에서는 픽업 진행 불가 상태 표시

---

### 8.3 GPS 정확도가 낮음

#### 상황

실내, 지하, 고층 건물 주변 등으로 인해 위치 오차가 큼

#### 시스템 대응

- 위치 정확도 낮음 표시
- 탑승자에게 더 개방된 장소로 이동 요청 가능
- 운전자에게 참고용 안내 제공

---

### 8.4 탑승자가 이동 중임

#### 상황

탑승자가 도보로 이동하거나 출구를 바꾸는 중임

#### 시스템 대응

- 일정 조건 이상 위치가 변경되면 최신 위치 반영
- 과도한 재경로를 방지하기 위한 갱신 기준 적용

---

### 8.5 차량 접근이 어려운 위치임

#### 상황

탑승자가 골목, 차도 진입 불가 구역, 건물 내부 등 차량이 접근하기 어려운 지점에 있음

#### 시스템 대응

- 현재 위치 그대로 보여주되, 향후 차량 접근 가능 지점 추천 기능 확장 가능
- MVP에서는 우선 현재 위치 전달에 집중

---

### 8.6 네트워크 불안정

#### 상황

한쪽 또는 양쪽 사용자의 네트워크 연결이 약함

#### 시스템 대응

- 마지막 갱신 시간 표시
- 위치 갱신 지연 안내
- 재연결 시 최신 정보 반영

---

### 8.7 세션 종료 후 링크 재접속

#### 상황

픽업 완료 후 링크에 다시 접속함

#### 시스템 대응

- 만료된 세션임을 안내
- 위치 공유 비활성화

---

## 9. MVP 기준 핵심 플로우

초기 버전에서는 다음 흐름이 끊김 없이 작동하는 것이 가장 중요하다.

1. 운전자가 픽업 세션을 생성할 수 있다.
2. 탑승자가 링크를 통해 위치 공유를 시작할 수 있다.
3. 운전자가 탑승자의 위치를 지도에서 볼 수 있다.
4. 운전자가 해당 위치를 기준으로 이동할 수 있다.
5. 픽업 완료 시 세션이 안전하게 종료된다.

즉, MVP의 핵심은 “설명 없이 사람 위치를 받아 그 사람에게 도달하는 경험”을 성립시키는 데 있다.

---

## 10. 향후 고도화 가능한 플로우

초기 버전 이후에는 다음과 같은 흐름 고도화를 고려할 수 있다.

- 차량 접근 가능 지점 자동 추천
- 운전자와 탑승자의 양방향 위치 가시화 강화
- 예상 도착 시간 정밀화
- 도착 알림/간단 메시지 기능
- 공항, 행사장, 캠퍼스 등 장소 특화 픽업 플로우
- 다인 픽업 시나리오 추가

---

## 11. 정리

본 서비스의 유저 플로우는 “장소 탐색”이 아니라 “사람과의 만남 성사”를 중심으로 설계되어야 한다.  
따라서 단순한 지도 탐색 흐름이 아닌, 실시간 위치 공유 세션과 운전자-탑승자 간 역할 분리를 바탕으로 사용자 흐름을 정의하는 것이 중요하다.

핵심은 다음과 같다.

- 운전자는 탑승자를 목적지처럼 인식한다.
- 탑승자는 복잡한 설명 없이 자신의 위치를 공유한다.
- 시스템은 두 사람의 만남이 성사될 때까지 상태를 연결한다.

이 문서는 이후 화면 설계, 기능 정의, 예외 처리 설계, MVP 범위 조정의 기초 자료로 활용한다.
