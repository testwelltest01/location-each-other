# 세션 상태 정의서

## 1. 문서 목적

본 문서는 실시간 위치추적형 픽업 앱에서 **픽업 세션(Pickup Session)** 의 상태(State)를 정의하고,  
각 상태에서의 시스템 동작, 사용자 행동 가능 범위, 상태 전이 조건, 예외 처리 기준을 명확히 규정하기 위한 문서이다.

이 문서는 다음 목적을 가진다.

- 프론트엔드/백엔드/디자인이 동일한 세션 개념을 사용하도록 한다.
- 세션의 생명주기(lifecycle)를 일관되게 관리한다.
- 실시간 위치 공유, 링크 접속, 세션 종료, 예외 상황을 상태 단위로 통제한다.
- 향후 API 명세, DB 설계, 상태관리 로직, QA 체크리스트의 기준 문서로 활용한다.

---

## 2. 세션 개념 정의

### 2.1 픽업 세션(Pickup Session)이란

픽업 세션이란,  
**운전자(Driver)가 탑승자(Passenger)를 픽업하기 위해 생성하는 일시적 실시간 위치 공유 단위**를 의미한다.

하나의 세션은 다음 정보를 중심으로 동작한다.

- 세션 생성자(운전자)
- 세션 참여자(탑승자)
- 초대 링크 또는 세션 진입 수단
- 탑승자의 실시간 위치
- 운전자의 지도 화면에서의 추적 정보
- 세션 시작 시각 / 종료 시각 / 만료 시각
- 세션 상태(State)

---

## 3. 세션 상태 관리 원칙

### 3.1 상태 관리 기본 원칙

- 하나의 세션은 **항상 하나의 대표 상태**만 가진다.
- 상태 전이는 사전에 정의된 이벤트에 의해서만 발생한다.
- 세션 상태는 **서버를 기준(source of truth)** 으로 관리한다.
- 프론트엔드는 서버 상태를 구독하거나 주기적으로 동기화한다.
- 일시적인 UI 표시 상태(로딩, 지도 확대 여부 등)는 세션 상태와 분리한다.

### 3.2 상태 설계 원칙

세션 상태는 다음 질문에 답할 수 있어야 한다.

- 세션이 아직 시작되지 않았는가?
- 탑승자가 세션에 진입했는가?
- 위치 공유가 실제로 시작되었는가?
- 현재 실시간 추적이 가능한가?
- 픽업이 완료되었는가?
- 세션이 만료되었거나 강제 종료되었는가?

---

## 4. 세션 상태 목록

본 서비스의 세션 상태는 아래와 같이 정의한다.

1. `CREATED`
2. `LINK_SHARED`
3. `PASSENGER_JOINED`
4. `LOCATION_PERMISSION_PENDING`
5. `LOCATION_SHARING_ACTIVE`
6. `LOCATION_SIGNAL_LOST`
7. `COMPLETED`
8. `CANCELLED`
9. `EXPIRED`

---

## 5. 상태별 정의

---

### 5.1 `CREATED`

#### 정의

운전자가 픽업 세션을 생성했지만, 아직 탑승자에게 링크가 전달되었거나 진입이 발생하지 않은 상태.

#### 진입 조건

- 운전자가 세션 생성 버튼을 누름
- 서버가 세션 ID를 발급함
- 세션 기본 정보 저장 완료

#### 사용자 관점 의미

- 운전자: 세션 생성 완료, 공유 준비 상태
- 탑승자: 아직 세션에 접근하지 않음

#### 허용 동작

- 운전자 링크 생성/복사/공유
- 세션 취소
- 세션 기본 정보 조회

#### 제한 동작

- 실시간 위치 추적 불가
- 탑승자 위치 표시 불가

#### 다음 상태 전이

- 링크 공유 성공 → `LINK_SHARED`
- 운전자 세션 취소 → `CANCELLED`
- 일정 시간 내 사용 없음 → `EXPIRED`

---

### 5.2 `LINK_SHARED`

#### 정의

운전자가 탑승자에게 세션 링크를 공유한 상태.  
단, 아직 탑승자가 링크에 접속했는지는 보장되지 않음.

#### 진입 조건

- `CREATED` 상태에서 링크 공유 액션 수행
- 또는 링크 복사 후 공유 완료 이벤트 기록

#### 사용자 관점 의미

- 운전자: 탑승자의 진입을 기다리는 상태
- 탑승자: 링크를 받았을 수 있으나 아직 미접속

#### 허용 동작

- 운전자 링크 재공유
- 세션 취소
- 세션 상태 조회

#### 제한 동작

- 실시간 위치 수신 불가
- ETA 계산 불가
- 지도에서 탑승자 표시 불가

#### 다음 상태 전이

- 탑승자 링크 접속 성공 → `PASSENGER_JOINED`
- 운전자 취소 → `CANCELLED`
- 링크 만료 → `EXPIRED`

---

### 5.3 `PASSENGER_JOINED`

#### 정의

탑승자가 링크를 통해 세션에 진입했지만, 아직 위치 권한 허용 또는 위치 송신이 완료되지 않은 상태.

#### 진입 조건

- 탑승자가 세션 링크 열기 성공
- 세션 유효성 검증 통과
- 탑승자 클라이언트가 세션 참여 등록 완료

#### 사용자 관점 의미

- 운전자: 탑승자가 세션에 들어왔음을 확인 가능
- 탑승자: 세션 화면 진입 완료, 위치 공유 준비 단계

#### 허용 동작

- 탑승자 위치 권한 요청
- 탑승자 세션 나가기
- 운전자 대기 화면 확인

#### 제한 동작

- 실시간 추적 아직 불완전
- 위치 데이터가 없으므로 정확한 경로 갱신 불가

#### 다음 상태 전이

- 위치 권한 요청 시작 → `LOCATION_PERMISSION_PENDING`
- 탑승자 이탈 → `CANCELLED` 또는 `EXPIRED` 정책 적용
- 링크 유효시간 초과 → `EXPIRED`

---

### 5.4 `LOCATION_PERMISSION_PENDING`

#### 정의

탑승자가 세션에는 입장했지만, 위치 권한을 아직 승인하지 않았거나 시스템으로부터 위치 권한 응답을 기다리는 상태.

#### 진입 조건

- `PASSENGER_JOINED` 상태에서 위치 권한 요청 UI 표시
- OS 권한 요청 진행 중 또는 사용자 판단 대기 중

#### 사용자 관점 의미

- 운전자: “탑승자가 들어왔지만 아직 위치를 공유하지 않음”
- 탑승자: 위치 권한 허용 여부를 선택하는 상태

#### 허용 동작

- 권한 허용
- 권한 거부
- 권한 재요청 안내 확인
- 세션 종료

#### 제한 동작

- 위치 전송 불가
- 운전자 실시간 추적 불가

#### 다음 상태 전이

- 권한 허용 + 첫 위치 획득 성공 → `LOCATION_SHARING_ACTIVE`
- 권한 거부 지속 → 정책상 `CANCELLED` 또는 세션 유지
- 시간 초과 → `EXPIRED`

#### 비고

권한 거부가 발생했다고 즉시 세션을 종료할지,  
재시도 유도 상태를 둘지는 MVP 정책에 따라 다를 수 있다.  
초기 버전에서는 일정 시간 내 권한 허용이 없으면 `EXPIRED` 또는 `CANCELLED` 처리하는 것을 권장한다.

---

### 5.5 `LOCATION_SHARING_ACTIVE`

#### 정의

탑승자의 위치가 정상적으로 수집 및 전송되고 있으며, 운전자가 실시간으로 추적 가능한 상태.

#### 진입 조건

- 위치 권한 허용 완료
- 첫 위치 좌표 수집 성공
- 서버가 유효한 위치 업데이트를 수신함

#### 사용자 관점 의미

- 운전자: 지도에서 탑승자 위치를 실시간 확인 가능
- 탑승자: 자신의 위치가 운전자에게 공유 중임을 인지 가능

#### 허용 동작

- 실시간 위치 업데이트
- ETA 계산/갱신
- 지도상 상대 위치 표시
- 세션 종료
- 목적지 근접 상태 표시
- 위치 갱신 품질 모니터링

#### 제한 동작

- 없음 (정상 운영 상태)

#### 다음 상태 전이

- 위치 송신 중단/네트워크 불안정/갱신 지연 → `LOCATION_SIGNAL_LOST`
- 운전자 또는 탑승자가 픽업 완료 처리 → `COMPLETED`
- 운전자 강제 종료 → `CANCELLED`
- 세션 최대 지속 시간 초과 → `EXPIRED`

#### 핵심 기준

이 상태는 본 서비스의 핵심 운영 상태이며,  
지도 UI, ETA, 거리 계산, 근접 알림 등 대부분의 핵심 기능은 이 상태에서만 활성화된다.

---

### 5.6 `LOCATION_SIGNAL_LOST`

#### 정의

세션은 아직 살아 있으나, 탑승자의 위치 업데이트가 일정 시간 이상 수신되지 않아  
실시간 추적의 신뢰도가 떨어진 상태.

#### 진입 조건

- 마지막 위치 갱신 이후 일정 시간 초과
- 네트워크 단절
- GPS 비활성화
- 앱 백그라운드/절전/브라우저 제한 등으로 인한 위치 송신 중단

#### 사용자 관점 의미

- 운전자: 마지막 위치는 보이지만 현재 위치는 신뢰하기 어려움
- 탑승자: 위치 공유가 불안정하거나 중단되었을 가능성 있음

#### 허용 동작

- 마지막 수신 위치 표시
- “위치 신호 약함/끊김” 안내
- 재연결 시도
- 세션 수동 종료

#### 제한 동작

- ETA 정확도 저하
- 실시간 위치 기반 자동 판단 기능 제한
- 근접 판단 정확도 저하

#### 다음 상태 전이

- 위치 업데이트 재개 성공 → `LOCATION_SHARING_ACTIVE`
- 사용자가 픽업 완료 처리 → `COMPLETED`
- 운전자 종료 → `CANCELLED`
- 장시간 복구 실패 → `EXPIRED`

#### 운영 기준 예시

- 10초 이상 위치 미수신: 경고
- 30초 이상 위치 미수신: `LOCATION_SIGNAL_LOST`
- 5분 이상 미복구: `EXPIRED` 후보

> 실제 시간 기준은 서비스 테스트 후 조정한다.

---

### 5.7 `COMPLETED`

#### 정의

운전자와 탑승자의 픽업이 정상적으로 완료되어 세션이 종료된 상태.

#### 진입 조건

- 운전자 “픽업 완료” 버튼 선택
- 탑승자 탑승 완료 확인
- 또는 근접 조건과 수동 확인을 통해 완료 처리

#### 사용자 관점 의미

- 픽업 목적 달성
- 위치 공유 종료
- 세션 정리 단계

#### 허용 동작

- 세션 요약 조회
- 후기/피드백
- 세션 기록 저장 정책에 따른 최소 정보 보관

#### 제한 동작

- 위치 재공유 불가
- 실시간 추적 불가
- 세션 재활성화 불가

#### 다음 상태 전이

- 없음 (종료 상태)

---

### 5.8 `CANCELLED`

#### 정의

운전자 또는 시스템 정책에 의해 세션이 정상 완료 전에 중도 종료된 상태.

#### 진입 조건

- 운전자가 세션 취소
- 탑승자 참여 철회
- 잘못 생성된 세션 종료
- 운영 정책상 강제 종료

#### 사용자 관점 의미

- 픽업 진행 중단
- 실시간 위치 공유 중단

#### 허용 동작

- 취소 사유 조회
- 세션 종료 화면 표시

#### 제한 동작

- 위치 공유 재개 불가
- 기존 세션 재사용 불가

#### 다음 상태 전이

- 없음 (종료 상태)

---

### 5.9 `EXPIRED`

#### 정의

세션이 유효 시간 내 정상적으로 진행되지 않았거나, 장시간 방치/미응답/미복구 상태로 인해 자동 만료된 상태.

#### 진입 조건

- 링크 만료 시간 초과
- 세션 최대 유지 시간 초과
- 장시간 위치 송신 없음
- 탑승자 미진입 상태 장기 지속

#### 사용자 관점 의미

- 세션이 더 이상 유효하지 않음
- 재사용 불가, 새 세션 생성 필요

#### 허용 동작

- 만료 안내
- 새 세션 생성 유도

#### 제한 동작

- 링크 재사용 불가
- 위치 공유 불가
- 상태 복구 불가

#### 다음 상태 전이

- 없음 (종료 상태)

---

## 6. 상태 전이 규칙

### 6.1 상태 전이 다이어그램 개요

```text
CREATED
  └─(링크 공유)→ LINK_SHARED
       └─(탑승자 링크 접속)→ PASSENGER_JOINED
            └─(위치 권한 요청 시작)→ LOCATION_PERMISSION_PENDING
                 └─(권한 허용 + 첫 위치 수신)→ LOCATION_SHARING_ACTIVE
                      ├─(위치 수신 지연/끊김)→ LOCATION_SIGNAL_LOST
                      │    └─(위치 복구)→ LOCATION_SHARING_ACTIVE
                      ├─(픽업 완료)→ COMPLETED
                      ├─(운전자 종료)→ CANCELLED
                      └─(시간 초과)→ EXPIRED

CREATED / LINK_SHARED / PASSENGER_JOINED / LOCATION_PERMISSION_PENDING
  ├─(운전자 취소)→ CANCELLED
  └─(유효시간 만료)→ EXPIRED

LOCATION_SIGNAL_LOST
  ├─(복구 성공)→ LOCATION_SHARING_ACTIVE
  ├─(픽업 완료)→ COMPLETED
  ├─(운전자 취소)→ CANCELLED
  └─(장시간 미복구)→ EXPIRED
```

---

## 7. 종료 상태(Terminal State)

아래 상태는 종료 상태로 정의한다.

- `COMPLETED`
- `CANCELLED`
- `EXPIRED`

종료 상태에 진입한 세션은 재활성화할 수 없으며,
필요 시 새로운 세션을 생성해야 한다.

## 8. 상태별 UI 표시 원칙

### 8.1 운전자 앱 UI 기준

- `CREATED` / `LINK_SHARED`
  - “탑승자 접속 대기 중”

- `PASSENGER_JOINED`
  - “탑승자 접속 완료”

- `LOCATION_PERMISSION_PENDING`
  - “탑승자가 위치 공유를 허용하는 중”

- `LOCATION_SHARING_ACTIVE`
  - 지도/실시간 위치/거리/ETA 표시

- `LOCATION_SIGNAL_LOST`
  - 마지막 위치 + 신호 끊김 안내

- `COMPLETED`
  - 픽업 완료 메시지

- `CANCELLED`
  - 세션 취소 메시지

- `EXPIRED`
  - 세션 만료, 새 세션 생성 유도

### 8.2 탑승자 웹/앱 UI 기준

- `PASSENGER_JOINED`
  - 세션 진입 완료 안내

- `LOCATION_PERMISSION_PENDING`
  - 위치 권한 허용 안내

- `LOCATION_SHARING_ACTIVE`
  - “내 위치 공유 중”

- `LOCATION_SIGNAL_LOST`
  - 위치 공유 불안정 안내

- `COMPLETED`
  - 픽업 완료 안내

- `CANCELLED`
  - 세션 종료 안내

- `EXPIRED`
  - 링크 만료 안내

## 9. 서버 상태 관리 원칙

### 9.1 단일 진실 원천

세션 상태는 서버 DB 또는 세션 상태 저장소에서 관리한다.
클라이언트는 서버 상태를 기준으로 화면을 렌더링한다.

### 9.2 상태 변경 기록

모든 상태 전이는 이벤트 로그로 남긴다.

예시:

- session_created
- link_shared
- passenger_joined
- location_permission_requested
- first_location_received
- location_signal_lost
- location_signal_restored
- session_completed
- session_cancelled
- session_expired

### 9.3 상태 전이 검증

허용되지 않은 상태 전이는 서버에서 차단한다.

예시:

- `COMPLETED` → `LOCATION_SHARING_ACTIVE` 불가
- `EXPIRED` → `PASSENGER_JOINED` 불가
- `CANCELLED` → `LOCATION_PERMISSION_PENDING` 불가

## 10. 타임아웃 및 자동 전환 정책(초안)

아래 수치는 초기 제안값이며, 실제 운영 및 테스트를 통해 조정한다.

- 세션 생성 후 미사용 상태 유지: 10분 → `EXPIRED`
- 링크 공유 후 탑승자 미접속: 15분 → `EXPIRED`
- 권한 요청 후 미응답: 3분 → `EXPIRED`
- 위치 갱신 없음 30초: `LOCATION_SIGNAL_LOST`
- 위치 갱신 없음 5분 이상: `EXPIRED`
- 세션 최대 지속 시간: 60분 → `EXPIRED`

## 11. 예외 처리 원칙

### 11.1 권한 거부

- 탑승자가 위치 권한을 거부하면 재시도 UI 제공
- 일정 시간 내 허용되지 않으면 세션 만료 또는 취소 처리

### 11.2 잘못된 링크

- 존재하지 않는 세션 ID: 접근 차단
- 만료된 링크: `EXPIRED` 안내
- 이미 종료된 세션: 종료 상태 안내

### 11.3 네트워크 단절

- 마지막 유효 위치는 임시 표시 가능
- 실시간 추적은 비정상 상태로 표기
- 복구 시 즉시 `LOCATION_SHARING_ACTIVE` 복귀

### 11.4 중복 접속

- 동일 탑승자의 중복 세션 진입 시 정책 필요
- 초기 버전에서는 최신 접속 세션만 유효 처리하거나, 단일 디바이스 접속만 허용하는 방안을 권장

## 12. 개발 시 주의사항

### 12.1 상태와 화면 단계를 혼동하지 않는다

예를 들어 로딩 중, 지도 렌더링 중, 권한 팝업 열림 등은 UI 상태이지 세션 상태가 아니다.

### 12.2 상태 전이와 이벤트를 분리한다

상태는 결과이고, 이벤트는 상태를 바꾸는 원인이다.

예:

- 이벤트: first_location_received
- 결과 상태: `LOCATION_SHARING_ACTIVE`

### 12.3 위치 존재와 위치 신뢰도는 다르다

마지막 좌표가 남아 있다고 해서 세션이 정상 추적 상태인 것은 아니다.
따라서 위치 데이터 보유 여부와 실시간 추적 가능 여부를 분리해서 판단해야 한다.

## 13. 향후 확장 가능 상태

추후 고도화 시 아래 상태를 별도로 도입할 수 있다.

- `DRIVER_APPROACHING`
  - 운전자가 매우 근접한 상태

- `PASSENGER_MOVING`
  - 탑승자가 빠르게 이동 중인 상태

- `AUTO_COMPLETION_CANDIDATE`
  - 근접 조건 충족으로 완료 후보 상태

- `RECONNECTING`
  - 위치 신호 복구 시도 중 상태

단, MVP에서는 상태 수를 과도하게 늘리지 않기 위해 본 문서의 9개 상태만 우선 적용한다.

## 14. 최종 정리

본 서비스의 세션은 다음 흐름을 따른다.

- 생성된다.
- 공유된다.
- 탑승자가 진입한다.
- 위치 권한이 허용된다.
- 실시간 위치 공유가 활성화된다.
- 필요 시 신호 끊김 상태를 거친다.
- 완료되거나, 취소되거나, 만료된다.

즉, 본 앱의 핵심은 단순한 링크 공유가 아니라
**“짧은 시간 동안만 유효한 실시간 위치 추적 세션”** 을 안정적으로 생성·운영·종료하는 것이다.

세션 상태 정의서는 그 중심 규칙을 고정하는 문서이며,
이후 API 설계, DB 모델링, 상태관리 구현, QA 테스트는 모두 본 문서를 기준으로 파생된다.
