# 기능 정의서

## 1. 문서 목적

본 문서는 픽업 특화 위치 기반 서비스의 핵심 기능을 정의하기 위한 문서이다.  
서비스 개요와 유저 플로우를 바탕으로, 사용자가 실제로 경험하게 될 기능을 세부 단위로 분리하고 각 기능의 목적, 동작 방식, 입력값, 출력값, 상태 변화, 예외 상황을 정리한다.

이 문서의 목적은 다음과 같다.

- 서비스의 핵심 기능을 구조적으로 정의한다.
- MVP 범위에서 반드시 구현되어야 할 기능을 명확히 한다.
- 화면 설계, API 설계, 데이터 모델링, 개발 우선순위 결정의 기준을 제공한다.
- 정상 흐름과 예외 흐름을 기능 단위에서 해석할 수 있도록 한다.

---

## 2. 기능 구조 개요

본 서비스의 기능은 크게 다음 다섯 영역으로 구성된다.

1. 픽업 세션 관리 기능
2. 위치 공유 기능
3. 실시간 지도 및 경로 안내 기능
4. 픽업 상태 관리 기능
5. 예외 처리 및 보조 기능

각 영역은 운전자와 탑승자의 역할에 따라 다르게 동작하며, 하나의 실시간 픽업 세션 안에서 상호 연결된다.

## 4. 기능 상세 정의

---

### F-01. 픽업 세션 생성

#### 기능 목적

운전자가 특정 탑승자를 픽업하기 위한 실시간 세션을 시작할 수 있도록 한다.

#### 사용자

- 운전자

#### 기능 설명

운전자가 앱에서 픽업 시작을 선택하면 시스템은 하나의 픽업 세션을 생성한다.  
이 세션은 이후 탑승자 초대, 위치 공유, 경로 안내, 픽업 완료까지의 전체 흐름을 관리하는 단위가 된다.

#### 입력

- 운전자의 픽업 시작 요청

#### 출력

- 고유한 픽업 세션 생성
- 세션 상태: `CREATED`

#### 상태 변화

- 없음 → `CREATED`

#### 성공 조건

- 세션이 정상 생성되어 이후 링크 발급이 가능해야 한다.

#### 예외 상황

- 네트워크 오류로 세션 생성 실패
- 중복 요청 발생

#### 비고

- 초기 MVP에서는 하나의 운전자당 한 번에 하나의 활성 세션만 허용하는 방식도 고려할 수 있다.

---

### F-02. 초대 링크 생성 및 공유

#### 기능 목적

운전자가 탑승자에게 세션 참여를 요청할 수 있도록 한다.

#### 사용자

- 운전자

#### 기능 설명

세션 생성 후 시스템은 탑승자가 접속할 수 있는 고유 링크를 생성한다.  
운전자는 이를 복사하거나 외부 메신저/문자를 통해 전송할 수 있다.

#### 입력

- 세션 ID
- 링크 생성 요청

#### 출력

- 고유 URL 또는 토큰 기반 초대 링크
- 세션 상태: `INVITED`

#### 상태 변화

- `CREATED` → `INVITED`

#### 성공 조건

- 생성된 링크를 탑승자가 접속할 수 있어야 한다.
- 링크는 특정 세션과 1:1로 연결되어야 한다.

#### 예외 상황

- 링크 생성 실패
- 이미 만료된 세션에 대한 링크 요청
- 중복 공유

#### 비고

- 보안상 링크는 일회성 또는 시간 제한 정책을 둘 수 있다.

---

### F-03. 링크 기반 세션 접속

#### 기능 목적

탑승자가 별도 복잡한 절차 없이 세션에 진입할 수 있도록 한다.

#### 사용자

- 탑승자

#### 기능 설명

탑승자는 전달받은 링크를 클릭하여 픽업 세션에 접속한다.  
앱 설치 없이 웹으로 열리는 구조도 MVP에서 고려 가능하다.

#### 입력

- 초대 링크 클릭

#### 출력

- 세션 접속 화면 진입
- 세션 유효성 검증 결과
- 세션 상태: `PASSENGER_CONNECTED`

#### 상태 변화

- `INVITED` → `PASSENGER_CONNECTED`

#### 성공 조건

- 유효한 링크라면 탑승자가 즉시 접속 가능해야 한다.

#### 예외 상황

- 링크 만료
- 존재하지 않는 세션
- 이미 종료된 세션
- 중복 접속

#### 비고

- 이 기능은 사용자 진입장벽을 낮추는 핵심 요소이다.

---

### F-04. 위치 권한 요청 및 획득

#### 기능 목적

탑승자의 현재 위치를 수집하기 위해 시스템 권한을 확보한다.

#### 사용자

- 탑승자

#### 기능 설명

탑승자가 세션에 접속하면 시스템은 위치 권한을 요청한다.  
탑승자가 권한을 허용하면 이후 위치 공유 기능을 수행할 수 있다.

#### 입력

- 위치 권한 요청 동의 여부

#### 출력

- 권한 허용 / 권한 거부 상태
- 세션 상태 갱신 가능

#### 상태 변화

- `PASSENGER_CONNECTED` → `LOCATION_PERMISSION_GRANTED`
  또는
- `PASSENGER_CONNECTED` → `LOCATION_PERMISSION_DENIED`

#### 성공 조건

- 위치 권한이 정상 허용되어 현재 위치를 읽을 수 있어야 한다.

#### 예외 상황

- 사용자가 권한을 거부함
- 기기 설정상 위치 서비스 비활성화
- 브라우저/OS 정책으로 권한 수집 불가

#### 비고

- 권한 요청 전 위치가 왜 필요한지 간단히 안내해야 한다.

---

### F-05. 실시간 위치 공유 시작/종료

#### 기능 목적

탑승자의 현재 위치를 운전자에게 전달할 수 있도록 한다.

#### 사용자

- 탑승자 / 시스템

#### 기능 설명

위치 권한 허용 후 탑승자가 위치 공유를 시작하면, 시스템은 일정 주기 또는 조건에 따라 현재 위치를 수집하고 세션에 반영한다.  
픽업이 완료되거나 사용자가 수동으로 종료하면 위치 공유는 중단된다.

#### 입력

- 위치 권한 허용
- 위치 공유 시작 요청
- 현재 GPS 좌표
- 종료 요청 또는 세션 종료 이벤트

#### 출력

- 실시간 위치 데이터
- 공유 상태: 시작 / 유지 / 종료

#### 상태 변화

- `LOCATION_PERMISSION_GRANTED` → `SHARING_ACTIVE`
- `SHARING_ACTIVE` → `SHARING_ENDED`

#### 성공 조건

- 운전자가 최신 위치를 확인할 수 있어야 한다.
- 종료 시 더 이상 위치가 전송되지 않아야 한다.

#### 예외 상황

- GPS 수신 불안정
- 배터리 절약 모드로 갱신 중단
- 백그라운드 전환 시 위치 갱신 제한
- 네트워크 끊김

#### 비고

- 위치 갱신 주기와 이동 거리 임계값은 추후 조정 가능한 정책값으로 설계하는 것이 바람직하다.

---

### F-06. 운전자 지도 화면에서 탑승자 위치 표시

#### 기능 목적

운전자가 탑승자의 실시간 위치를 직관적으로 확인할 수 있도록 한다.

#### 사용자

- 운전자

#### 기능 설명

탑승자의 위치 공유가 시작되면 운전자의 지도 화면에 현재 위치와 탑승자의 위치를 함께 표시한다.

#### 입력

- 운전자 현재 위치
- 탑승자 현재 위치
- 세션 상태 정보

#### 출력

- 지도 위 운전자 위치
- 지도 위 탑승자 위치
- 거리 또는 예상 도착 시간 정보

#### 상태 변화

- `SHARING_ACTIVE` 상태에서 기능 활성화

#### 성공 조건

- 두 사용자의 위치 관계를 시각적으로 명확히 볼 수 있어야 한다.

#### 예외 상황

- 탑승자 위치 미수신
- 위치 좌표는 있으나 정확도 낮음
- 지도 로딩 실패

#### 비고

- MVP에서는 지도 위 마커 표시와 기본 거리 정보까지만 포함해도 충분하다.

---

### F-07. 현재 위치 기반 픽업 경로 안내

#### 기능 목적

운전자가 탑승자에게 이동할 수 있도록 경로를 제공한다.

#### 사용자

- 운전자

#### 기능 설명

운전자는 탑승자 위치를 기준으로 길안내를 시작할 수 있다.  
이 경로는 운전자의 현재 위치에서 탑승자의 현재 위치 또는 해당 좌표를 기준으로 계산된다.

#### 입력

- 운전자 현재 위치
- 탑승자 현재 위치

#### 출력

- 픽업 경로
- 예상 소요 시간
- 예상 도착 거리/시간

#### 상태 변화

- `SHARING_ACTIVE` 상태에서 길안내 시작
- 세션 상태: `DRIVER_NAVIGATING`

#### 성공 조건

- 운전자가 별도 주소 입력 없이 이동을 시작할 수 있어야 한다.

#### 예외 상황

- 경로 탐색 실패
- 도로 정보 없음
- 차량 진입 불가 지역

#### 비고

- MVP에서는 내부 지도를 쓰거나 외부 내비게이션 앱 연동 방식도 검토 가능하다.

---

### F-08. 위치 변경 시 경로 갱신

#### 기능 목적

탑승자가 움직일 경우 경로를 최신 위치 기준으로 반영한다.

#### 사용자

- 시스템 / 운전자

#### 기능 설명

탑승자의 위치가 일정 거리 이상 변경되거나, 일정 시간이 경과했을 때 시스템은 최신 위치를 반영한다.  
필요 시 경로를 재탐색하여 운전자에게 새로운 픽업 경로를 제공한다.

#### 입력

- 이전 위치
- 현재 위치
- 갱신 조건(시간/거리 기준)

#### 출력

- 최신 위치 반영
- 경로 재계산 또는 재탐색

#### 상태 변화

- `DRIVER_NAVIGATING` 유지
- 내부적으로 목적지 좌표 갱신

#### 성공 조건

- 위치 변경이 너무 늦지도, 너무 잦지도 않게 반영되어야 한다.

#### 예외 상황

- 탑승자가 매우 빠르게 이동
- 위치 흔들림으로 목적지 진동 발생
- 운전 중 과도한 재탐색으로 혼란 유발

#### 비고

- 이 기능은 서비스의 핵심 차별점이지만, 지나치게 민감하게 작동하면 오히려 UX를 해칠 수 있다.

---

### F-09. 픽업 상태 표시

#### 기능 목적

운전자와 탑승자가 현재 픽업 진행 상황을 쉽게 이해할 수 있도록 한다.

#### 사용자

- 운전자 / 탑승자

#### 기능 설명

시스템은 현재 세션의 상태를 사용자에게 노출한다.  
예를 들어 “상대방 접속 대기 중”, “위치 공유 중”, “운전자 이동 중”, “근처 도착”, “픽업 완료” 등으로 표시할 수 있다.

#### 입력

- 세션 상태값
- 위치 상태값

#### 출력

- 상태 메시지
- UI 배지/라벨/안내 문구

#### 상태 변화

- 세션 상태 변화에 따라 자동 갱신

#### 성공 조건

- 사용자가 현재 무엇을 기다리는 상태인지 즉시 이해할 수 있어야 한다.

#### 예외 상황

- 상태 업데이트 지연
- 실제 상태와 화면 표시 불일치

#### 비고

- 이 기능은 불안을 줄이고 흐름 이해를 돕는 UX 핵심 요소이다.

---

### F-10. 픽업 완료 처리 및 세션 종료

#### 기능 목적

두 사용자가 만나면 안전하게 위치 공유와 세션을 종료한다.

#### 사용자

- 운전자 / 시스템

#### 기능 설명

운전자가 픽업 완료를 선택하거나 일정 조건에서 시스템이 종료 흐름을 유도하면, 세션을 종료하고 위치 공유를 중단한다.

#### 입력

- 픽업 완료 버튼 클릭
  또는
- 세션 종료 조건 충족

#### 출력

- 위치 공유 중단
- 세션 상태: `COMPLETED`
- 종료 화면 또는 안내

#### 상태 변화

- `DRIVER_NAVIGATING` 또는 `NEARBY` → `COMPLETED`
- 이후 `CLOSED`

#### 성공 조건

- 종료 이후 위치 데이터가 더 이상 송신되지 않아야 한다.
- 사용자가 세션 종료를 명확히 인지해야 한다.

#### 예외 상황

- 종료 요청 실패
- 종료 후에도 위치 송신 지속
- 양측 중 한쪽 화면에 종료 상태 미반영

#### 비고

- 개인정보 보호 관점에서 매우 중요한 기능이다.

---

### F-11. 접속 대기 상태 안내

#### 기능 목적

운전자가 탑승자의 접속 전 상황을 이해하도록 돕는다.

#### 사용자

- 운전자

#### 기능 설명

탑승자가 아직 링크를 열지 않았거나, 위치 공유를 시작하지 않은 경우 운전자에게 현재 대기 상태를 표시한다.

#### 입력

- 탑승자 접속 여부
- 위치 공유 시작 여부

#### 출력

- “상대방 접속 대기 중”
- “위치 권한 요청 중”
- “아직 위치가 공유되지 않았습니다” 등의 메시지

#### 상태 변화

- `INVITED`
- `PASSENGER_CONNECTED`
- `LOCATION_PERMISSION_GRANTED` 전후 상태 반영

#### 성공 조건

- 운전자가 시스템이 멈췄다고 오해하지 않아야 한다.

#### 예외 상황

- 상태 동기화 지연
- 이미 접속했는데 대기 상태로 표시됨

#### 비고

- 초기 신뢰 형성에 중요하다.

---

### F-12. 예외 상태 안내

#### 기능 목적

위치 공유 실패나 시스템 문제를 사용자에게 이해 가능한 방식으로 안내한다.

#### 사용자

- 운전자 / 탑승자

#### 기능 설명

다양한 예외 상황 발생 시 단순 오류 코드가 아니라 사용자가 취할 수 있는 행동을 포함한 안내를 제공한다.

#### 대표 예외 유형

- 위치 권한 거부
- GPS 정확도 낮음
- 네트워크 불안정
- 세션 만료
- 링크 오류
- 경로 탐색 실패

#### 입력

- 시스템 오류 이벤트
- 위치/네트워크 상태

#### 출력

- 예외 메시지
- 재시도 버튼 또는 안내 문구

#### 성공 조건

- 사용자가 현재 왜 진행이 안 되는지 이해할 수 있어야 한다.
- 가능한 경우 다음 행동을 제시해야 한다.

#### 비고

- 서비스 신뢰성과 사용성에 직접적인 영향을 준다.

## 5. 기능 간 관계

각 기능은 독립적으로 보이지만 실제로는 다음 흐름으로 연결된다.

1. F-01 픽업 세션 생성
2. F-02 초대 링크 생성 및 공유
3. F-03 링크 기반 세션 접속
4. F-04 위치 권한 요청 및 획득
5. F-05 실시간 위치 공유 시작
6. F-06 지도에서 위치 표시
7. F-07 경로 안내 시작
8. F-08 위치 변경 시 갱신
9. F-09 상태 표시
10. F-10 픽업 완료 및 종료
11. F-11, F-12는 전 과정의 상태 보조 및 예외 안내 기능으로 작동

즉, 본 서비스의 기능 구조는 하나의 세션 흐름 안에서 순차적이면서도 상태 기반으로 연결된 구조이다.

## 8. 정리

본 서비스의 기능은 단순한 위치 공유 기능의 집합이 아니라,  
**사람을 목적지로 삼아 실시간으로 만남을 성사시키기 위한 세션 기반 기능 구조**로 이해해야 한다.

핵심은 다음 세 가지이다.

- 세션이 만들어져야 한다.
- 탑승자의 현재 위치가 안전하게 공유되어야 한다.
- 운전자가 그 위치를 바탕으로 실제로 도달할 수 있어야 한다.

이 기능 정의서는 이후 화면 설계서, API 명세서, 데이터 모델 설계, 개발 우선순위 수립의 기초 자료로 활용한다.
