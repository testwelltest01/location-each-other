# 컴포넌트 정의서

## 1. 문서 목적

본 문서는 픽업 특화 위치 기반 서비스의 화면을 구성하는 공통 UI 요소를 정의하기 위한 문서이다.  
화면 설계서와 와이어프레임 초안을 바탕으로, 반복적으로 사용되는 시각적/기능적 단위를 컴포넌트로 분리하여 각 요소의 목적, 사용 맥락, 상태, 속성, 예외 사항을 정리한다.

이 문서의 목적은 다음과 같다.

- 서비스 전반에서 일관되게 사용되는 UI 단위를 정의한다.
- 화면별 중복 설계를 줄이고 재사용 가능한 구조를 마련한다.
- 디자이너와 개발자가 동일한 UI 단위를 공통 언어로 사용할 수 있도록 한다.
- 이후 디자인 시스템, Figma 컴포넌트, 프론트엔드 공통 컴포넌트 설계의 기준을 제공한다.

---

## 2. 컴포넌트 설계 원칙

### 2.1 역할 중심 분리

컴포넌트는 모양이 아니라 역할을 기준으로 분리한다.  
예를 들어 단순한 “회색 박스”가 아니라, “상태를 보여주는 배지”, “핵심 행동을 수행하는 버튼”, “세션 정보를 담는 패널”처럼 기능을 기준으로 정의한다.

### 2.2 상태 표현 우선

본 서비스는 실시간 세션 기반 서비스이므로, 컴포넌트는 단순 장식보다 현재 상태를 사용자에게 명확히 전달할 수 있어야 한다.

### 2.3 최소 조작성

특히 운전자 화면에서는 조작 수를 줄이고 빠르게 인식 가능한 UI를 우선해야 한다.  
따라서 컴포넌트는 복잡한 상호작용보다 즉시 이해되는 구조를 지향한다.

### 2.4 공통성과 확장성 균형

초기 MVP에서는 단순한 형태로 시작하되, 이후 상태 증가나 기능 확장에 대응할 수 있도록 컴포넌트의 속성과 변형(variant)을 고려한다.

### 2.5 플랫폼 독립성

본 문서는 특정 프레임워크(예: React Native, Flutter, SwiftUI)에 종속되지 않으며, 기획/디자인/개발 공통 기준 수준에서 정의한다.

---

## 3. 컴포넌트 분류 체계

본 서비스의 컴포넌트는 다음과 같이 분류한다.

1. 레이아웃 컴포넌트
2. 액션 컴포넌트
3. 상태/정보 컴포넌트
4. 지도/위치 컴포넌트
5. 입력/권한 컴포넌트
6. 피드백/예외 컴포넌트

## 5. 컴포넌트 상세 정의

---

### C-01. 상단바 (Header Bar)

#### 목적

화면의 제목과 기본 네비게이션 정보를 제공한다.

#### 사용 화면

- 홈 화면
- 링크 공유 화면
- 연결 대기 화면
- 위치 권한 요청 화면
- 픽업 완료 화면
- 예외 화면 전반

#### 주요 요소

- 화면 제목
- 뒤로가기 버튼(필요 시)
- 닫기 버튼(필요 시)
- 선택적 보조 액션

#### 주요 속성

- `title`
- `showBackButton`
- `showCloseButton`
- `rightAction`

#### 상태

- 기본
- 뒤로가기 포함
- 닫기 포함
- 액션 포함

#### 설계 메모

- 운전자 화면에서는 상단바가 과도하게 복잡하면 안 된다.
- 탑승자 링크 진입 화면에서는 신뢰감을 줄 수 있는 간결한 제목이 중요하다.

---

### C-02. 기본 버튼 (Primary Button)

#### 목적

현재 화면에서 가장 중요한 핵심 행동을 수행하게 한다.

#### 사용 예시

- 픽업 시작
- 세션 생성
- 위치 공유 시작하기
- 위치 권한 허용
- 길안내 시작
- 픽업 완료

#### 주요 속성

- `label`
- `enabled/disabled`
- `loading`
- `fullWidth`
- `size`

#### 상태

- 기본
- 비활성
- 로딩
- 강조

#### 설계 메모

- 한 화면에 Primary Button은 원칙적으로 1개를 우선한다.
- 운전자 화면에서는 버튼 크기를 크게 하고 오터치 가능성을 줄여야 한다.

---

### C-03. 보조 버튼 (Secondary Button)

#### 목적

핵심 행동 다음으로 중요한 보조 동작을 제공한다.

#### 사용 예시

- 링크 다시 공유
- 공유하기
- 새 픽업 시작
- 다시 시도

#### 주요 속성

- `label`
- `icon(optional)`
- `enabled/disabled`

#### 상태

- 기본
- 비활성
- 보조 강조

#### 설계 메모

- Primary와 시각적으로 구분되어야 한다.
- 주요 흐름을 방해하지 않는 수준의 존재감이 적절하다.

---

### C-04. 텍스트 버튼 (Text Button)

#### 목적

덜 중요한 보조 액션이나 취소/이전 동작을 제공한다.

#### 사용 예시

- 취소
- 이전으로
- 닫기
- 나중에 할게요

#### 주요 속성

- `label`
- `emphasisLevel`

#### 상태

- 기본
- 경고형(필요 시)

#### 설계 메모

- 너무 자주 쓰면 주요 행동 유도가 흐려진다.
- 예외 화면에서 재시도보다 약한 선택지로 사용하기 적절하다.

---

### C-05. 하단 고정 액션 바 (Bottom Action Bar)

#### 목적

화면 하단에 핵심 액션을 고정 배치하여 사용자가 언제든 중요한 행동을 수행할 수 있게 한다.

#### 사용 화면

- 링크 공유 화면
- 실시간 픽업 지도 화면
- 위치 공유 진행 화면

#### 주요 요소

- Primary Button 1개
- Secondary Button 0~1개
- 선택적 상태 정보

#### 주요 속성

- `primaryAction`
- `secondaryAction`
- `sticky`
- `safeAreaAware`

#### 상태

- 단일 버튼형
- 이중 버튼형
- 버튼 + 상태형

#### 설계 메모

- 지도 화면에서는 화면 가림이 심하지 않도록 높이 조절이 중요하다.

---

### C-06. 상태 배지 (Status Badge)

#### 목적

현재 세션 또는 위치 상태를 짧고 즉각적으로 전달한다.

#### 사용 예시

- 위치 공유 중
- 연결 대기 중
- 근처 도착
- 위치 정확도 낮음
- 마지막 갱신됨

#### 주요 속성

- `label`
- `type`
- `icon(optional)`

#### 상태 유형 예시

- 정보형
- 성공형
- 경고형
- 중립형

#### 설계 메모

- 너무 많은 배지를 동시에 노출하면 해석이 어려워진다.
- 최대 2개 정도를 우선 노출하는 구조가 적절하다.

---

### C-07. 상태 패널 (Status Panel)

#### 목적

현재 흐름의 상태와 다음 행동을 더 자세히 설명한다.

#### 사용 예시

- 상대방이 아직 링크를 열지 않았습니다
- 위치 권한 요청 중입니다
- 운전자가 이 위치를 보고 이동 중입니다
- 네트워크 상태가 불안정합니다

#### 주요 요소

- 상태 제목
- 보조 설명
- 선택적 액션 버튼

#### 주요 속성

- `title`
- `description`
- `severity`
- `action(optional)`

#### 상태

- 정보
- 경고
- 오류
- 완료

#### 설계 메모

- 배지보다 설명이 필요한 상태를 담는다.
- 대기 화면, 오류 상태, 공유 진행 화면에서 자주 쓰인다.

---

### C-08. 정보 카드 (Info Card)

#### 목적

요약 정보나 보조 정보를 카드 형태로 보여준다.

#### 사용 예시

- 최근 세션 정보
- 현재 픽업 안내
- 보조 설명
- 픽업 완료 후 안내

#### 주요 요소

- 제목
- 본문 텍스트
- 선택적 아이콘

#### 주요 속성

- `title`
- `body`
- `icon(optional)`
- `compact`

#### 설계 메모

- 장문의 설명 대신 짧은 정보 덩어리로 나누는 데 유용하다.

---

### C-09. 링크 공유 카드 (Link Share Card)

#### 목적

생성된 픽업 링크를 보기 쉽고 복사/공유하기 쉽게 제공한다.

#### 사용 화면

- 링크 공유 화면

#### 주요 요소

- 링크 텍스트
- 복사 버튼
- 공유 버튼

#### 주요 속성

- `url`
- `copyAction`
- `shareAction`

#### 상태

- 기본
- 복사 완료
- 공유 실패

#### 설계 메모

- 너무 긴 링크는 축약 표시하되 복사는 원본 기준으로 동작해야 한다.

---

### C-10. 지도 뷰 컨테이너 (Map View Container)

#### 목적

내 위치, 상대 위치, 경로 등 공간 정보를 시각적으로 제공한다.

#### 사용 화면

- 실시간 픽업 지도 화면
- 근접/도착 확인 화면
- 탑승자 위치 공유 진행 화면(선택)
- 운전자 접근 확인 화면(선택)

#### 주요 요소

- 지도 배경
- 위치 마커
- 경로
- 확대/축소 제어(선택)

#### 주요 속성

- `showDriverLocation`
- `showPassengerLocation`
- `showRoute`
- `interactive`
- `zoomLevel`

#### 상태

- 위치 표시형
- 경로 표시형
- 근거리 확대형
- 로딩형

#### 설계 메모

- MVP에서는 지도가 너무 많은 기능을 갖기보다 핵심 정보 전달 역할에 집중해야 한다.

---

### C-11. 위치 마커 (Location Marker)

#### 목적

지도 위에서 운전자/탑승자/목적 위치를 구분해서 표시한다.

#### 사용 예시

- 운전자 현재 위치
- 탑승자 현재 위치
- 기준 위치
- 추천 지점(향후 확장)

#### 주요 속성

- `type` (driver/passenger/target/recommended)
- `label(optional)`
- `accuracyRadius(optional)`

#### 상태

- 기본
- 선택됨
- 정확도 낮음
- 최근 갱신 안 됨

#### 설계 메모

- 운전자와 탑승자 마커는 절대 혼동되면 안 된다.
- 정확도 원(radius)을 추가할지 여부는 이후 UX 검토 필요하다.

---

### C-12. 거리/ETA 패널 (Distance ETA Panel)

#### 목적

운전자에게 현재 얼마나 남았는지 요약 제공한다.

#### 사용 화면

- 실시간 픽업 지도 화면
- 근접/도착 확인 화면

#### 주요 요소

- 남은 거리
- 예상 도착 시간
- 선택적 현재 상태

#### 주요 속성

- `distance`
- `eta`
- `statusText(optional)`

#### 상태

- 기본
- 갱신 중
- 정확도 낮음
- 값 없음

#### 설계 메모

- 숫자 정보는 한눈에 읽혀야 하므로 복잡한 문장보다 요약형 수치가 적합하다.

---

### C-13. 권한 요청 카드 (Permission Prompt Card)

#### 목적

위치 권한이 왜 필요한지 사용자에게 사전 설명한다.

#### 사용 화면

- 위치 권한 요청 화면
- 권한 거부 안내 화면

#### 주요 요소

- 권한 필요 설명
- 허용 버튼
- 취소 또는 설정 이동 버튼

#### 주요 속성

- `title`
- `description`
- `primaryAction`
- `secondaryAction`

#### 상태

- 기본
- 권한 거부 후 재요청형
- 설정 이동 유도형

#### 설계 메모

- 시스템 권한 팝업 자체보다 이 카드가 사용자의 거부감을 낮추는 역할을 한다.

---

### C-14. 로딩/대기 인디케이터 (Loading Indicator)

#### 목적

사용자가 시스템 처리 중임을 인지하게 한다.

#### 사용 예시

- 세션 생성 중
- 탑승자 접속 대기 중
- 위치 수신 대기 중
- 경로 계산 중

#### 주요 형태

- 스피너
- 점 애니메이션
- 상태 텍스트 결합형

#### 주요 속성

- `message`
- `size`
- `inline/fullscreen`

#### 상태

- 짧은 로딩
- 긴 대기
- 상태 메시지 포함

#### 설계 메모

- 연결 대기 화면에서는 단순 로딩보다 상태 설명과 함께 쓰는 것이 더 적절하다.

---

### C-15. 오류 안내 카드 (Error Message Card)

#### 목적

오류 원인과 다음 행동을 사용자에게 안내한다.

#### 사용 예시

- 링크 만료
- 네트워크 오류
- 경로 탐색 실패
- 위치 수신 실패

#### 주요 요소

- 오류 제목
- 설명 문구
- 재시도 버튼
- 이전/닫기 버튼

#### 주요 속성

- `title`
- `description`
- `retryAction(optional)`
- `secondaryAction(optional)`

#### 상태

- 경고형
- 오류형
- 재시도 가능형
- 종료 유도형

#### 설계 메모

- 기술적 오류 코드를 직접 노출하기보다 사용자가 할 수 있는 행동을 먼저 보여줘야 한다.

---

### C-16. 완료 상태 카드 (Completion Card)

#### 목적

작업이 성공적으로 끝났음을 보여주고 종료감을 제공한다.

#### 사용 예시

- 픽업 완료
- 위치 공유 종료

#### 주요 요소

- 완료 아이콘
- 완료 메시지
- 보조 안내
- 종료 또는 다음 액션 버튼

#### 주요 속성

- `title`
- `description`
- `primaryAction`
- `secondaryAction(optional)`

#### 상태

- 단순 완료형
- 완료 + 후속 행동형

#### 설계 메모

- 위치 관련 서비스에서는 종료 명확성이 신뢰에 중요하다.

---

### C-17. 근접 상태 카드 (Nearby Status Card)

#### 목적

두 사용자가 서로 가까워졌음을 강조해 마지막 만남을 돕는다.

#### 사용 화면

- 근접/도착 확인 화면
- 운전자 접근 확인 화면

#### 주요 요소

- 근접 상태 제목
- 현재 거리 또는 도착 예상
- 짧은 행동 안내

#### 주요 속성

- `title`
- `distance(optional)`
- `eta(optional)`
- `hintText`

#### 상태

- 근접
- 도착 임박
- 거의 도착

#### 설계 메모

- 이 컴포넌트는 긴 설명보다 짧고 강한 메시지가 적합하다.

---

### C-18. 마지막 갱신 시간 라벨 (Last Updated Label)

#### 목적

사용자에게 현재 정보가 얼마나 최신인지 알려준다.

#### 사용 화면

- 실시간 픽업 지도 화면
- 위치 공유 진행 화면

#### 주요 요소

- 예: `마지막 갱신 10초 전`

#### 주요 속성

- `timestamp`
- `format`
- `staleThreshold`

#### 상태

- 최신
- 약간 지연
- 오래됨

#### 설계 메모

- 실시간 서비스에서 정보 신뢰도를 높이는 작은 요소다.
- 오랫동안 갱신이 없을 경우 경고형 문구로 전환할 수 있다.

## 8. 향후 확장 고려 사항

### 8.1 디자인 시스템화

이후 서비스가 확장되면 버튼, 배지, 카드, 패널 계열 컴포넌트를 토큰 기반 디자인 시스템으로 정리할 수 있다.

### 8.2 상태 유형 증가

현재는 연결 대기, 위치 공유, 근접, 완료 정도만 정의했지만, 추후 다인 픽업이나 차량 접근 추천 기능이 들어오면 상태 종류가 더 세분화될 수 있다.

### 8.3 지도 상호작용 강화

초기에는 지도 상호작용을 최소화하되, 이후 특정 위치 고정, 추천 지점 선택, 진입 가능 구역 표시 등으로 확장될 수 있다.

### 8.4 플랫폼별 최적화

모바일 앱과 모바일 웹에서 컴포넌트 크기, 버튼 위치, 권한 요청 흐름이 달라질 수 있으므로 추후 플랫폼별 분기 정의가 필요하다.

---

## 9. 정리

본 서비스의 컴포넌트 정의는 단순한 UI 요소 정리가 아니라,  
**실시간 픽업 경험을 안정적이고 일관되게 제공하기 위한 재사용 가능한 인터페이스 단위 정의**에 해당한다.

핵심은 다음과 같다.

- 화면은 컴포넌트의 조합으로 구성된다.
- 상태 표현 컴포넌트가 일반 앱보다 특히 중요하다.
- 지도와 버튼보다 “상태를 어떻게 보여줄 것인가”가 UX 완성도를 좌우한다.
- 컴포넌트를 먼저 정리하면 이후 디자인과 개발 속도가 크게 빨라진다.

이 문서는 이후 Figma 컴포넌트 구조 설계, 프론트엔드 공통 UI 설계, 디자인 시스템 문서화의 기준 자료로 활용한다.
